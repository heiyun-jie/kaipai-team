# 00-236 测试环境人工验收与 GO/NO-GO

> 状态：`READY / AWAITING_MANUAL_ACCEPTANCE`（自动前置通过，等待用户人工测试与明确 `GO / NO-GO`）
>
> 上游：`00-234`、`00-235`；下游：`00-237`

## 1. 概述

本 Spec 对已完成生产副本迁移的测试环境执行自动门禁和人工业务验收，覆盖历史账号、新账号、小程序、后台和公开分享，输出可审计的正式发布 GO/NO-GO。人工验收只证明冻结候选，验收后任何代码、迁移或配置变化都会使结论失效。

## 2. 用户故事

作为业务负责人，我希望在正式发布前亲自验证所有核心页面和历史数据，而不是只依赖接口测试。

作为发布操作人，我希望人工验收有明确账号、步骤、证据和严重级别，不能凭“看起来没问题”进入生产。

## 3. 功能需求

### 3.1 验收前环境证明

**验收标准**：

- WHEN 开始人工验收 THEN `00-235` 状态为 `TEST_DATA_READY`，candidateId 和证据 SHA256 可核对。
- WHEN 测试小程序启动 THEN API Base URL 为 test API，正式线上版本保持不变。
- WHEN 测试后台启动 THEN API 和静态资源均来自测试域名。
- WHEN 任一环境目标不明确 THEN 不开始人工验收。

### 3.2 覆盖历史账号兼容

**验收标准**：

- WHEN 历史账号登录 THEN 会话、个人资料、头像、经历、intro、素材和实名状态正确。
- WHEN 保存历史资料 THEN 未编辑的旧字段、媒体和作品不被清空。
- WHEN 打开旧分享页 THEN 原内容仍可匿名访问。
- WHEN 使用历史素材创建演员卡 THEN 素材可选、可预览并正确回读。

### 3.3 覆盖新账号完整流程

**验收标准**：

- WHEN 新账号使用 THEN 登录/注册、资料、经历、intro 和素材上传可完成。
- WHEN 执行演员卡 7 步 THEN 主视觉、资料、作品、照片、视频、附件和设置均可保存/回读。
- WHEN 生成、预览、发布和分享 THEN 页面结构、资源、匿名访问和复制创建符合当前 Spec。
- WHEN 取消上传或返回 THEN 不产生锁死提示、脏绑定或丢失已保存数据。

### 3.4 覆盖后台与受控外部能力

**验收标准**：

- WHEN 后台登录 THEN 7 页正式导航、角色权限和配置读取正常。
- WHEN 测试 AI/短信/实名 THEN 遵守 `00-234` 白名单/禁用策略，不产生未授权正式副作用。
- WHEN 外部能力被禁用 THEN UI/API 显示明确测试环境状态，不表现为未知 500。

### 3.5 统一缺陷分级与裁决

**验收标准**：

- WHEN 出现 P0/P1 THEN 立即 `NO-GO`。
- WHEN 出现 P2 THEN 必须有明确接受人、影响面和限期，否则 `NO-GO`。
- WHEN 修复任何缺陷改变候选 THEN 使原人工验收失效，回到 `00-231` 重新冻结并按影响重跑。
- WHEN 仅补充不改变运行态的证据 THEN 可沿用候选，但需记录原因。

### 3.6 输出签署结论

**验收标准**：

- WHEN 全部必测项通过 THEN 用户明确签署 `GO`，记录 candidateId、测试时间和证据包 SHA256。
- WHEN 用户尚未签署 THEN 状态保持 `AWAITING_APPROVAL`，不得进入生产。
- WHEN 输出截图/日志 THEN 不包含 PII、Token、身份证号或完整签名 URL。

## 4. 非功能需求

- 微信开发者工具核验遵守桌面非干扰规则：不得置顶、抢焦点、控制整屏或使用桌面坐标自动化。
- 每个核心步骤记录预期、实际、结果和证据 id。
- 验收时保留正式环境运行，不停止或切换生产服务。

## 5. 约束条件

- 人工验收不能替代自动 Schema、数据和包体门禁。
- 生产副本数据视为敏感数据，截图必须裁剪/脱敏。
- 没有用户明确 GO，不允许推断授权正式发布。
