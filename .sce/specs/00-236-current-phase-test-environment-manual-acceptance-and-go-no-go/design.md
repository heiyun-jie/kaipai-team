# 00-236 测试环境人工验收与 GO/NO-GO - 技术设计

_Requirements: 3.1-3.6, 4, 5_

## 1. 验收状态机

```text
NOT_READY -> READY -> IN_PROGRESS -> AWAITING_APPROVAL -> GO
                          |                    |
                          +------> NO_GO <-----+
```

只有 `GO` 能解锁 `00-237`。自动测试通过只到 `READY`，不能代替用户签署。

## 2. 测试账号矩阵

使用至少两类账号：

- 历史账号：来自生产副本，具备非空档案/媒体/作品中的至少两类；证据只用内部 alias。
- 新测试账号：仅存在 `kaipai_test`，用于产生写入和完整流程。

可增加实名已通过、未实名、无素材等边界账号。不得在文档写手机号、姓名和证件信息。

## 3. 自动门禁先行

人工操作前依次核对：

1. `00-234` 隔离 preflight passed。
2. `00-235` Schema/data/API evidence passed。
3. 执行 `verify-test-miniapp-acceptance.py --candidate-id <candidate-id>`，结果必须是 `READY_FOR_MANUAL_ACCEPTANCE / exit 0`。
4. 该准入结果必须证明冻结 `mini-program-test`、工作区 build、固定 dev、项目级编译缓存和实时测试请求绑定同一 Candidate。
5. 小程序 type-check、专项 verify 和包体审计已包含在该 Candidate 的冻结证据中；release 产物未在本阶段上传。

自动门禁失败时不进入人工页面测试。

## 4. 人工验收清单

### 4.1 历史兼容

- 登录、会话恢复和退出。
- 个人资料旧头像/字段显示，保存后重新进入。
- 演艺经历列表、新增、编辑、删除非关键测试项。
- 自我介绍读取和保存。
- 历史照片/视频在三列素材库展示、预览、选择。
- 历史旧分享详情匿名打开。

### 4.2 新流程

- 新账号初始化。
- 照片/视频/PDF 上传、取消、失败重试、删除。
- 演员卡 7 步逐项保存和返回回读。
- 生成页和公开页共同渲染器、长页滚动、图片/视频/PDF。
- 发布、分享、复制创建、草稿继续编辑。

### 4.3 后台

- 登录和 session。
- 7 页正式导航可达。
- 用户、分享内容、风格模板、运营动作、系统设置的核心只读/受控写操作。
- AI 配置在测试环境的禁用/白名单状态。

## 5. 视觉证据规则

优先使用微信开发者工具内部非抢焦点 MCP、产物核验和用户提供截图。需要可见窗口时遵守已有授权和桌面非干扰规则。截图：

- 使用测试 alias 避免暴露姓名/手机号。
- 不展示身份证、Token、签名 URL。
- 文件名包含 candidateId、route、caseId。
- 每个失败证据附关联日志 correlation id，不附原始敏感 payload。

## 6. 缺陷分级

| 等级 | 示例 | 结论 |
|---|---|---|
| P0 | 数据丢失、越权、生产污染 | 立即 NO-GO |
| P1 | 核心流程不可完成、历史数据不可见、500 | NO-GO |
| P2 | 有明确绕行的非核心缺陷 | 明确接受后才可 GO |
| P3 | 不影响功能的轻微显示问题 | 可登记后 GO |

任何 backend/admin/frontend 输入或工作区 build 相对冻结候选发生变化，准入脚本必须返回 `CANDIDATE_REFREEZE_REQUIRED`，原 GO/验收计数失效。按变更影响至少重跑相关自动门禁和完整人工核心矩阵；数据库/合同变化必须从 `00-235` 重跑。

## 7. 签收记录

记录至少包含：candidateId、manifest SHA256、test evidence SHA256、自动门禁摘要、人工 case 总数/通过/失败/豁免、缺陷清单、用户结论和时间。状态可为 `GO`、`NO_GO`、`AWAITING_APPROVAL`。

## 8. 回滚边界

本阶段不切生产。NO-GO 后停止测试继续写入，保留现场证据；测试环境是否恢复/重建由修复影响决定，不改生产运行态。
