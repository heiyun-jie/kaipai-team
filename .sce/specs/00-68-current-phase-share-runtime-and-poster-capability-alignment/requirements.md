# 00-68 当前阶段分享运行时与海报能力对齐（Current Phase Share Runtime and Poster Capability Alignment）

> 状态：已完成 | 优先级：最高 | 依赖：00-62 current-phase-minimal-share-card-mvp-alignment，00-63 current-phase-share-card-latest-state-alignment，00-64 current-phase-actor-card-editor-boundary-alignment，00-66 current-phase-share-theme-request-fact-investigation，00-67 current-phase-share-theme-semantic-alignment
> 记录目的：把“分享链可打开但演员档案接口断裂”和“分享海报能力门禁与当前产品要求不一致”两个线上问题收口成同一条整改 Spec，防止继续靠页面兜底或局部隐藏按钮临时修补。

## 1. 背景

当前线上已出现两类真实运行时问题：

- `shareCardId -> /api/card/personalization` 可以成功返回，但继续读取 `/api/actor/{actorId}` 时，部分用户会返回 `演员档案不存在`
- 前端多个入口持续展示“分享海报”按钮，但后端 `poster` artifact 仍可能返回 `locked=true / lockReason=会员可生成定制海报`

这两类问题都不是单点 UI 文案错误，而是：

- 分享链事实源存在断裂
- 能力规则与展示规则不是同一来源

若不升为独立 Spec，后续极易继续出现：

- 页面 A 修了，页面 B 继续炸
- 后端能力没改，前端先放开按钮
- 数据脏记录未治理，运行时继续 500

## 2. 范围

### 2.1 本轮必须处理

- 收口分享公开链的运行时事实源
- 明确“有效 shareCard 不得因为缺少独立 actor_profile 记录而直接不可查看”
- 收口分享海报当前阶段的真实能力口径
- 统一前端首页、卡片列表、卡片编辑页的海报按钮展示与动作逻辑
- 明确后台 / 治理侧对分享链断裂数据的排查与修复责任

### 2.2 本轮不处理

- 全量重做公开页 UI
- 新增新的分享产物类型
- 扩展会员商业化规则
- 大规模重做 actor/profile 全域模型

## 3. 需求

### 3.1 分享链运行时完整性

- **R1** 只要 `shareCardId` 对应的分享卡片有效，公开分享链就必须返回可渲染的最小持卡人信息，不得出现 `personalization` 成功但 `actor detail` 再次 500 的断裂链路。
- **R2** 当前分享公开链必须收口到单一稳定事实源；前端不得继续依赖“先 personalization，再二跳 actor detail，且二跳可能失败”的脆弱组合。
- **R3** 若历史数据中存在 `user_share_card` 已创建但 `actor_profile` 缺失的用户，后端必须为分享链提供稳定 fallback 或聚合返回最小演员资料，而不是直接抛出“演员档案不存在”。
- **R4** 当前问题不得通过前端静默吞错、假造本地资料、或只对单页特殊兜底的方式修复。
- **R5** 需要有显式治理手段识别并修复“分享卡存在但演员档案缺失”的历史数据，而不是长期依赖运行时撞错。

### 3.2 分享页读取责任

- **R6** `pages/actor-profile/detail`、`pkg-card/actor-card/index` 以及依赖分享卡最新态的页面，必须消费同一套分享公开载荷，不得再让页面各自决定是否额外读 `/api/actor/{id}`。
- **R7** `share-card-latest` 相关共享 loader 必须服从新的运行时事实源，不得继续保留已证实会导致线上断裂的旧链路实现。
- **R8** 对分享链而言，“档案不存在”必须从运行时 500 风险降级为可治理、可回显、可补偿的状态；用户侧公开页不得直接暴露后端数据断裂异常。

### 3.3 分享海报能力口径

- **R9** 当前阶段“分享海报”能力必须按用户最新产品要求对齐为所有可分享卡片用户均可使用，不再保留会员专属门禁。
- **R10** 后端 `capability.canUseCustomPoster`、`artifacts.poster.locked` 与 `artifacts.poster.lockReason` 必须与当前产品口径完全一致，不得继续返回会员专属锁定态。
- **R11** 首页、卡片列表、卡片编辑页等所有前端入口，必须基于同一能力结果展示“分享海报”按钮；不得继续出现“按钮可见但点击后 toast 提示会员能力”的伪可用状态。
- **R12** 若未来产品再次改回分层能力，前端也必须遵循“不可用则隐藏或禁用态显式说明”的单一规则，不得再使用点击后才告知门禁的交互。

### 3.4 文案与治理对齐

- **R13** 所有“会员可生成定制海报”“会员海报能力”等当前阶段失效文案，必须从用户主链移除。
- **R14** 后台与状态文档必须明确：当前线上主风险不是“后端未发布”，而是“分享链事实源断裂 + 海报能力口径未对齐”。
- **R15** 本问题整改必须沉淀到 Spec、状态卡、执行记录与运行时证据，不得只停留在聊天说明。
