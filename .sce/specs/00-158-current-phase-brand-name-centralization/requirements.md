# 00-158 需求

## 目标

统一当前项目的品牌、小程序名称和分享卡片名称，避免 `剧名片`、`小程序卡片`、`演员名片` 等用户可见硬编码继续散落在小程序、后台和后端中。

## 目标命名

- 分享卡片对外标题：`开拍了名片`
- 小程序正式名称：`开拍了演员卡`
- 小程序简称：`开拍了`
- 品牌罗马字母展示：`KAIPAILE`
- 当前 AppID：`wx4dcc4e1066fd0fb9`

## 问题

- 小程序分享卡页面的微信分享标题由页面内逻辑拼接，当前会生成类似 `用户6737的经典写真集小程序卡片`。
- 小程序卡片预览和海报仍存在 `剧名片` 文案。
- 登录页、首页和海报预览仍存在旧罗马字母品牌 `JU MING PIAN`，登录页仍存在带空格的 `剧 名 片` 展示。
- 后台侧登录页、侧边栏、系统设置存在 `剧名片` 文案。
- 后端个性化分享产物 API 仍返回 `小程序卡片` 标签。
- 品牌名称没有集中配置，后续改名需要跨页面搜索替换，风险高。

## 验收标准

- 小程序核心分享链路中的分享卡标题使用 `开拍了名片`。
- 小程序源码中的核心品牌文案从统一配置读取，而不是页面局部常量。
- 后台核心壳层品牌文案从统一配置读取。
- 后端分享产物标签从统一品牌支持类读取。
- `kaipai-frontend/src`、`kaipai-admin/src`、`kaipaile-server/src/main/java` 中不得继续出现当前运行态品牌残留 `剧名片`。
- `kaipai-frontend/src` 中不得继续出现旧罗马字母品牌 `JU MING PIAN` 或带空格的旧品牌展示 `剧 名 片`。
- 登录页品牌 hero 使用 `开拍了` 与 `KAIPAILE`。
- 微信开发者工具打开的构建产物 `dist/dev/mp-weixin` 同步新 AppID 和新本地项目名称。
- 对微信公众平台侧的小程序名称/简称变更，在执行记录中明确说明：代码只能配置本地项目和运行态文案，微信分享面板底部的小程序官方名称仍以公众平台审核后的账号名称为准。
