# 3.0 小程序最终 UI 风格系统与交互视觉合同

> 状态：Spec 已创建，实施未开始。
> 上游调查：00-220-current-phase-miniapp-v3-final-ui-deep-investigation。
> 独立风格文档：docs/ui-style-guide-v3.md。

## 1. 概述

3.0 是「开拍了」小程序的最终 UI 定稿版本。它以本地视觉参考目录 C:\Users\33340\Desktop\开拍了\小程序UI图 的五张 PNG 为视觉基线，将当前 22 个实际注册路由、共享组件、TabBar 资源和操作状态收口到同一套蓝白专业演员作品集风格。

本 Spec 定义可执行的颜色、字体、间距、圆角、页面壳层、组件状态、图标和操作反馈合同。它不直接修改页面代码；代码实现须按本 Spec 和 docs/ui-style-guide-v3.md 另立执行任务。

## 2. 目标与非目标

### 2.1 目标

1. 让所有用户可达页面使用同一套蓝白主题 Token，消除旧棕米色、橙色选中态和页面级硬编码分裂。
2. 让首页、创建向导、参演作品、生活照片、个人中心五类参考图页面具备一致的信息层级和操作反馈。
3. 让 Tab 根页、普通内容页、向导页、媒体页和公开观看页拥有稳定、可复用的页面壳层。
4. 让每个按钮、卡片、Tab、上传入口、删除入口和列表操作都具备可验证的点击、loading、成功、失败和返回语义。
5. 为后续 UI 迁移提供单一风格文档、路由覆盖清单和静态验收门禁。

### 2.2 非目标

- 本 Spec 不恢复或删除历史业务能力，不改变后端接口和数据库结构。
- 本 Spec 不替代 00-213、00-214、00-215、00-218 对向导业务、附件、分享和资源上传的功能合同。
- 本 Spec 不把生成引擎占位图视为真实长图生成能力；生成结果仍需由独立功能 Spec 验收。
- 本 Spec 不要求一次提交完成全部 22 页实现，执行顺序由 tasks.md 的 T0-T4 控制。

## 3. 用户故事

- 作为演员，我希望从首页、名片夹、素材库或个人中心进入任何页面时，都能识别这是同一个产品，而不是在蓝白、棕米色和橙色界面之间跳转。
- 作为演员，我希望看到的上传、删除、排序、预览、继续编辑和发布入口都能给出明确反馈，不被静默失败或「即将开放」假入口阻断。
- 作为产品和研发维护者，我希望颜色、尺寸、组件状态和页面覆盖范围都有文档和静态检查，不依赖个人记忆还原视觉稿。

## 4. 功能需求

### 4.1 统一颜色 Token

**描述**：3.0 必须建立品牌蓝、文本、背景、边框、状态五组语义 Token。页面和共享组件只引用 Token，不直接复制颜色字面量。

**目标值**：

| Token | 值 | 主要用途 |
|---|---|---|
| brand | #2F6BFF | 主 CTA、选中态、进度、链接 |
| brand-strong | #145DFF | pressed、深色主按钮、关键强调 |
| brand-soft | #EEF2FF | 选中容器、提示背景、浅蓝区块 |
| canvas | #FFFFFF | 页面主背景 |
| surface-muted | #F6F7F9 | 列表底色、分组背景 |
| text-primary | #171A21 | 标题、正文 |
| text-secondary | #667080 | 描述、辅助信息 |
| text-tertiary | #8E8E93 | 占位、未完成状态 |
| border | #E8E8E8 | 卡片边框、输入框 |
| divider | #F0F0F0 | 内容分割 |
| success | #2E8A57 | 完成、成功 |
| warning | #E67E22 | 待确认、提示 |
| danger | #FF3B30 | 删除、失败、退出 |

**验收标准**：

- WHEN 扫描用户可达页面和共享组件的 release 源码 THEN 旧 #1D1814、#8C6F4F、#F5F3EE 不得作为默认视觉值出现。
- WHEN 页面需要颜色 THEN 必须引用 3.0 语义 Token；遗留颜色只能位于显式 legacy 命名空间并有迁移清单。
- WHEN 构建 dist/build 和 dist/dev THEN 两侧产物的颜色和 scoped hash 必须与源码对应，不得出现只改一侧的主题回退。

### 4.2 字体与信息层级

**描述**：所有页面使用系统无衬线字体；标题、正文、说明、标签和微文案按固定字号、字重和行高表达层级。

**验收标准**：

- Display 使用 48rpx/700，页面标题使用 36rpx/700，H1 使用 40rpx/700，H2 使用 32rpx/700，正文使用 28rpx/400，Caption 使用 24rpx/400，Micro 使用 22rpx/400。
- 同一页面不得用字号变化代替状态颜色；标题不得依赖负字距或 viewport 字体缩放。
- 文本在 iPhone SE 宽度和最大系统字号下不得溢出按钮、卡片或底部操作栏。

### 4.3 间距、圆角与层级

**描述**：3.0 默认采用 24rpx 页面左右边距、24rpx 卡片内边距、16rpx 连续卡片间距、32rpx 区块间距；五张本地参考图对应的首页、创建 Hub、参演作品、生活照片、个人中心主体使用 40rpx 页面左右边距，以匹配视觉稿的首屏留白。普通卡片圆角 16rpx，控件圆角 12rpx，胶囊使用 999rpx。

**验收标准**：

- WHEN 页面出现连续卡片 THEN 使用父级 gap 或统一 spacing Token，不能逐卡复制临时 margin。
- WHEN 页面有固定底部 CTA THEN 内容区域必须预留安全区，CTA 不遮挡最后一项内容。
- WHEN 验收五张本地参考图页面 THEN 页面主体左右留白为 40rpx，不能被通用 24rpx 默认值回退。
- 页面不得使用深色 Hero + 米色内容的旧骨架作为默认 3.0 页面结构。

### 4.4 页面壳层

**描述**：四个原生 Tab：首页、名片夹、素材库、个人，必须各自拥有可直接渲染的根页；非 Tab 页、向导页和公开观看页使用对应的 3.0 壳层。

**验收标准**：

- Tab 根页不通过中间 redirectTo 页面承载主要内容；素材库须有稳定的 Tab 返回和选中态。
- 标题型页面继续使用 KpPageNav；调用方不得重复拼胶囊占位、标题绝对定位和返回按钮。
- 向导 Hub 与 7 个步骤共享进度、底部 CTA、安全区、错误反馈和返回确认规则。
- 公开观看页在未登录、草稿、资源失效和网络失败时都有独立状态，不显示空白页面。

### 4.5 组件与状态

**描述**：KpButton、KpInput、KpStatusTag、KpConfirmDialog、KpBottomActionBar、KpPageNav 及上传、列表、空态组件必须以 3.0 Token 为唯一默认皮肤。

**验收标准**：

- 每个按钮至少定义 default、pressed、disabled、loading 四态；loading 时锁定重复点击。
- 每个上传、删除、排序和网络操作至少定义进行中、成功、失败重试和返回后回读状态。
- 空态必须给出下一步动作或明确不可操作原因，不得只展示装饰性插画。
- 删除、退出、替换等不可逆操作必须使用确认对话框，并在取消后保持原状态。

### 4.6 图标和媒体资源

**描述**：功能图标使用统一线性图标体系；TabBar 必须提供首页、名片夹、素材库、个人四项独立的未选中 / 选中资源。

**验收标准**：

- TabBar 选中资源为蓝色，不依赖橙色位图或 selectedColor 对 PNG 二次着色。
- 不使用 Emoji 作为功能图标；图标按钮必须有可读的 aria-label 或 tooltip 文案。
- 不同 Tab 不复用语义不一致的 rank.png；名片夹和素材库必须可区分。

### 4.7 操作闭环

**描述**：视觉稿中的入口必须对应真实 handler、目标路由或接口。若能力暂不交付，必须在产品裁决中移除入口或明确标记为未交付，不能保留假操作。

**验收标准**：

- 首页模板选择携带明确模板 / 背景标识；名片夹草稿支持删除；生活照片支持已裁决的素材库选择、上传、删除、排序和回读；作品支持剧照管理；视频支持预览和替换。
- 个人中心的帮助与反馈、设置、统计入口要么可达真实页面，要么从最终 UI 删除。
- 个人档案页消费入口 query 参数，或将入口文案改为实际落点。
- 生成页区分生成中、失败、占位和真实结果，不能把主视觉图伪装成长图生成结果。

## 5. 非功能需求

- 兼容微信基础库 >= 2.25.0，覆盖 iPhone SE 到 iPhone 15 Pro Max 和主流 Android 设备。
- 首屏渲染目标小于 1 秒；列表单次默认渲染不超过 10 条。
- 颜色、字号、间距、圆角和阴影变更必须可通过静态扫描发现。
- UI 改动后必须核对 src、dist/build/mp-weixin、dist/dev/mp-weixin 三侧；开发者工具同步前执行 00-219 的缓存清理和 scoped hash 检查。
- 涉及接口、数据库、已发布卡或公开观看页的改动必须先完成发版兼容评估。

## 6. 约束和决策门

1. 本 Spec 以 00-220 的 22 页真实 pages.json 基线为准；CURRENT_CONTEXT.md 等旧文档中的 20 页数字在实施前统一。
2. 00-221 的蓝白风格覆盖优先于 SHARED_CONVENTIONS.md 中的历史 Cinematic Glassmorphism 描述；实现阶段需同步回填全局约定，不能让两套默认值并行。
3. 旧分享详情页 pkg-card/ai-profile-card-detail 的保留、重皮肤或退场由 T0 产品裁决决定。
4. 生活照片素材库、排序、帮助与反馈、设置和真实长图生成均需明确交付批次；未裁决前不得把入口标成完成。
