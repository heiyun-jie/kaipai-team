# 名片夹草稿发布准备度与操作入口收口

## 1. 概述

`pages/card-list/index` 的草稿卡当前只提供“继续编辑 / 删除草稿”。列表响应只有总完成度，不能区分“必填步骤尚未完成”“必填步骤已完成但尚未生成”“已经生成、等待发布”三种状态，因此已具备发布条件的草稿也没有明确入口。

本 Spec 在不放宽生成和发布门禁的前提下，为名片夹列表增加只读准备度字段，并按状态提供“继续编辑 / 生成预览 / 预览并发布”。发布确认仍在生成预览页完成，不允许未生成草稿绕过预览直接调用发布接口。

## 2. 用户故事

- 作为演员，我希望在草稿列表直接看到当前下一步，不需要先猜完成度百分比。
- 作为已完成必填资料的演员，我希望从草稿卡直接进入生成预览。
- 作为已有生成结果的演员，我希望从草稿卡直接进入预览并发布。
- 作为发布维护者，我希望列表入口不削弱服务端“先生成、后发布”的强制门禁。

## 3. 功能需求

### 3.1 列表准备度事实源

- 后端 `ActorCardListItemDTO` 新增 `generateReady` 和 `publishReady` 两个只读布尔字段。
- `generateReady` 仅在草稿的必填步骤 1 主视觉、2 个人资料、3 参演作品、7 生成设置全部完成时为 `true`；可选步骤 4/5/6 不阻断生成。
- `publishReady` 仅在卡片仍为草稿且 `generatedPreviewUrl` 存在时为 `true`。
- 名片夹完成度中的参演作品必须读取 `actor_card_work` 真实行数，不得继续默认计为已完成。
- 前端字段保持可选；旧后端未返回字段时按 `false` 处理，保守回退继续编辑。

### 3.2 草稿操作分流

- WHEN `publishReady=true` THEN 草稿卡显示“继续编辑 / 预览并发布 / 删除草稿”。
- WHEN `publishReady=false && generateReady=true` THEN 草稿卡显示“继续编辑 / 生成预览 / 删除草稿”。
- WHEN 两个字段均不为 `true` THEN 草稿卡保持“继续编辑 / 删除草稿”。
- “生成预览”进入 `/pkg-actor-card/generate/index?cardId={id}`，由现有生成页提交生成任务。
- “预览并发布”进入 `/pkg-actor-card/generate/index?cardId={id}&preview=1`，由现有生成页展示结构化预览并保留发布确认。
- 点击草稿卡上层仍进入编辑 Hub；删除确认、失败重试和已发布卡操作保持不变。

### 3.3 发布安全

- 名片夹不得直接调用 `publishActorCard`，不得绕过生成预览页的内容确认。
- 后端发布接口继续要求 `generatedPreviewUrl`，本 Spec 不修改该门禁。
- 新字段只由服务端业务数据派生，前端不得根据 `completionPercentage` 自行推断发布资格。

## 4. 验收标准

- 后端单测覆盖生成准备、发布准备、缺少作品和已发布卡四种状态。
- 前端专项门禁覆盖三种草稿操作结构、目标路由、旧后端保守回退和不直调发布接口。
- `npm run type-check`、名片夹既有回归和后端 `ActorCardPublishServiceTest` 通过。
- 构建后固定 `dist/dev/mp-weixin/pages/card-list/index` 的 WXML/WXSS/JS 包含新操作文案和状态分流。
- MCP 产物核验确认唯一运行入口三件套完整且 scoped hash 状态一致。

## 5. 约束

- 遵循 `00-206` 的“完成必填步骤 -> 生成 -> 预览 -> 发布”流程。
- 遵循 `00-253` 的卡片上层信息区与底部横向操作栏布局。
- 不新增数据库字段、迁移、路由或发布接口。
- 后端响应只做增量字段扩展，旧前端继续兼容；新前端对旧后端安全降级。
- 日常测试只构建和核验固定 `kaipai-frontend/dist/dev/mp-weixin`。
- 本次前后端合同变化会使当前 Candidate 失效，完成后必须重新冻结并重跑全栈准入；正式发布继续等待用户明确授权。
