# 演员卡页面装修与双模式 AI 首图

> 状态：需求/设计草案，待用户确认；未开始实现、迁移、调用付费 AI、部署或上传。
> 2026-10-22 用户明确：内容渲染应由后端配置控制圆角、展示位置等，类似页面装修，不是仅配置圆角。
> 上游：00-140/142 后台模板编辑、00-228/229 共享正文、00-242 单一首图、00-245/248 内部扩图。

## 1. 目标

后台可视化维护演员卡页面，后端管理并发布结构化页面配置，小程序按配置和真实演员数据渲染。卡主生成预览和用户分享观看使用同一装修配置、同一渲染器。

首图支持两种模式：
1. 人物照片 + AI：使用人物照片生成首图，页面采用平台默认装修模板。
2. 人物照片 + 指定背景 + AI：以人物照片和后台背景图为两项输入合成首图，页面采用所选背景关联的装修模板。

默认模板也使用同一配置协议，而不是另一套硬编码页面。AI 产出人物场景图，不把姓名、作品、资料卡片或按钮烧进图片。

## 2. 已核实基线

- generate/index 和 view/index 共用 ActorCardRenderer，后端 owner preview / public view 共用 buildView。
- Renderer 仍按00-229七区绝对坐标和固定正文顺序渲染，不消费后台页面装修Schema。
- 后台已有 themeConfig / artifactPresetJson.pageConfig，可编辑主题、部分模块显隐与行动区；尚未贯通当前演员卡渲染器。
- 当前 actor_card_background 仅有风格、图片、缩略图、排序、启用等，未绑定装修模板版本。
- 当前扩图请求只有一个sourceImageUrl，不能直接等同于人物图+背景图双参考图合成。

## 3. 验收标准

### 3.1 页面装修
- 后台以模块面板、手机画布预览、属性面板编辑，不要求运营手写JSON。
- 配置覆盖模块显隐、正文排序、容器内位置/对齐、尺寸、圆角、间距、背景/文字颜色、字体层级、边框和阴影。
- Hero覆盖区支持受约束的位置/层级；长页正文按流式布局和排序展示，不能将整条长页按固定坐标铺死。
- 支持页面默认样式及单模块覆盖；未配置属性继承默认值；后台预览与小程序遵循同一布局协议。
- 首批模块包含首图、身份摘要、亮点、资料/简介、作品、照片/剧照、视频、PDF入口和合作信息。具体模块取舍仍需与用户参考图确认，不能默默丢失已有完整资料。

### 3.2 配置发布与消费
- 后端校验、保存草稿、预览、发布版本、回滚；未发布编辑不能影响公开页。
- 发布配置使用显式schemaVersion / templateId / templateVersion；背景资源与页面模板明确关联，不按URL猜配置。
- owner/public两个响应取得相同有效装修模型，但仍执行各自鉴权、隐私与已发布状态规则。
- 已支持模块的样式、顺序、位置等发布后无需重新上传小程序；新增组件类型或平台能力仍需前端开发发版。
- 未知或不兼容Schema必须安全降级，不能执行任意下发HTML/JS/CSS或让整页白屏。

### 3.3 AI输入与样式解耦
- 两种生成模式明确存储，人物身份与背景资源分别保存，不能让背景图占用人物来源字段。
- 双图合成必须有Provider真实支持和运行证据，不允许用单图扩图/前端叠图假冒双图合成。
- 后端统一封装AI，保留异步任务、幂等、防重复扣费、失败重试及旧结果隔离。
- 人物/背景/生成指令变更使对应旧生成结果失效；只改圆角/顺序/颜色等页面样式不重复调用AI。

### 3.4 兼容与验证
- 保留生成/发布状态机、公开草稿403/不存在404、联系/视频/附件隐私开关和真实数据来源。
- 保留分包自包含、原生image稳定性、图片不拉伸、长文本自适应、视口滚动与底栏安全区。
- 旧客户端忽略新增字段仍可用；旧卡没有装修字段时走已发布默认配置或明确兼容布局，不迁移业务数据冒充新卡。
- 新增持久化模型/SQL前完成兼容评估；迁移必须幂等，并提供正式环境预置与回滚说明，未经授权不执行部署/迁移。
- 旧00-229/249/250视觉断言需在新合同获批后登记被覆盖部分；当前草案不直接废弃旧门禁。
