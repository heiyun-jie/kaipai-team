# 历史演员卡自动扩图补偿与首图无畸变兜底

> 状态：实施中（2026-09-01）。
>
> 上游：`00-242`、`00-245`、`00-247`；下游：`00-236` 人工验收。

## 1. 概述

`00-245` 已把 AI 扩图收口为后端内部自动异步操作，但自动任务只在步骤 1 保存或 `source_image` 绑定替换后创建。测试卡 `cardId=1` 的素材首图在新后端部署前已经绑定，部署后只执行了演员卡生成，因此 `kaipai_test` 中没有 `expand_image` 任务，`expanded_image_url` 和来源指纹均为空。共享演员卡渲染器又把回退原图按固定 9:16 画布 `scaleToFill`，最终表现为人物被纵向拉伸。

本 Spec 为活跃历史草稿增加卡主动作驱动的幂等补偿，并保证扩图尚未完成、失败或结果失效时原图不发生几何拉伸。扩图仍是内部操作，不增加演员可见按钮、状态、轮询或 Provider 错误。

## 2. 用户故事

作为历史演员卡的卡主，我打开草稿或直接生成演员卡时，希望系统自动补齐当前首图对应的扩图任务，不需要重新选择或上传照片。

作为演员卡查看者，我希望扩图尚未完成时仍能看到比例正确的原图，而不是把原图强行拉成长图。

作为发布维护者，我希望补偿只由明确的卡主动作触发并按卡片与来源指纹幂等复用，禁止上线后批量扫描历史数据或由匿名公开访问消耗 AI Provider。

## 3. 功能需求

### 3.1 历史首图懒补偿

- WHEN 卡主读取一个有有效当前首图的草稿 THEN 后端在不改变读取响应的前提下请求一次内部自动扩图。
- WHEN 旧客户端跳过草稿读取而直接提交演员卡生成 THEN 生成入口也请求同一内部自动扩图。
- WHEN 当前来源已经存在相同 `actor_card_id + generation_mode + source_fingerprint` 的任务 THEN 必须复用现有任务，不重复调用 Provider。
- WHEN 当前来源没有任务 THEN 创建 `expand_image` 异步任务；接口不得等待 Provider 完成。
- WHEN 自动提交阶段异常 THEN 只记录内部日志，草稿读取和生成接口保持原有业务合同。

### 3.2 成本与访问边界

- 匿名公开页不得触发扩图任务。
- 名片夹批量列表、后台列表、定时启动和数据库迁移不得扫描并触发历史卡片扩图。
- 只有卡主对单张卡片执行草稿读取、步骤 1 保存、首图绑定替换或生成时才允许触发。
- Provider 失败继续进入内部任务状态；演员页面不得展示 AI 扩图、处理中、失败原因或重试入口。

### 3.3 无畸变首图兜底

- WHEN 共享演员卡渲染器展示任意可用首图 THEN 图片不得使用会改变原始宽高比的 `scaleToFill`。
- WHEN 有效扩图尚未完成、失败或来源指纹不匹配 THEN 页面可对原图做居中裁切，但不得纵向或横向拉伸。
- WHEN 有效扩图位于私有 COS 桶 THEN 后端响应组装时签发短时可读 URL，数据库仍只保存无签名稳定 URL。
- WHEN 扩图读 URL 无法签发 THEN 生成页、公开详情和名片夹封面回退当前来源图，不返回不可读扩图地址。
- 短时签名 URL 不得写回 `actor_card` 或生成任务表，不改变现有数据库合同。
- 生成页和公开页继续共用同一渲染器，Hero 的固定 750 x 1334 画布、覆盖层和正文结构不因本修复改变。

### 3.4 运行态与候选治理

- 修改后必须重新构建并核对 `src`、`dist/build/mp-weixin`、`dist/dev/mp-weixin` 三侧 Renderer，WXML/WXSS/JS 与 scoped hash 必须一致。
- 任何代码变化都使 Candidate `20260901-150906-v3-draft` 的人工验收失效；必须冻结全新 Candidate 后才能恢复 `AWAITING_MANUAL_ACCEPTANCE`。
- 新 Candidate 必须包含同一后端 JAR和小程序产物，并仅部署到 `kaipai-backend-test`、`kaipai_test` 和固定测试工程。

## 4. 验收标准

- 后端专项测试证明草稿读取和直接生成都会请求自动扩图，公开页与批量列表不会触发。
- 后端专项测试证明私有桶扩图在详情与列表响应中获得短时签名，签名异常回退来源图。
- 服务测试继续证明同一卡片、同一来源的任务幂等复用，失败任务受控重试，旧来源结果不能回写。
- 前端专项门禁证明共享 Renderer 不含 `mode="scaleToFill"`，生成页和公开页仍共用它。
- `npm run type-check`、演员卡专项门禁、`npm run build:mp-weixin`、包体审计及三侧等价检查通过。
- 新测试 Candidate 部署后，`cardId=1` 由卡主打开草稿即可产生与 `assetId=1` 当前来源指纹匹配的 `expand_image` 任务。
- 任务成功后 `actor_card.expanded_image_url` 与 `expanded_source_fingerprint` 均存在且指纹匹配；若 Provider 失败，页面仍保持原图比例正确且失败只在内部可观测。
- 正式容器、`kaipai_prod`、生产 Nginx 和正式小程序保持未变，正式发布状态仍为 `NOT_AUTHORIZED`。

## 5. 发版兼容与约束

- 不新增或修改前端 API 字段，不破坏旧小程序响应合同。
- 不新增数据库迁移；继续复用 `V20260901_001__actor_card_internal_auto_expand.sql` 的可空字段和唯一索引。
- 旧小程序仍可使用步骤保存、素材绑定和生成接口；新增后端触发属于幂等内部副作用。
- 生产发布后不会自动批量生成历史卡；只有卡主访问单卡草稿或生成时才懒补偿。
- 未获得明确 `GO`，不得执行 `00-237`、迁移生产数据库、切换正式 Nginx 或上传正式小程序。
