# 演员卡 Hero 个人简介摘要防硬截断

> 状态：已完成，Candidate `20260901-200255-v3-draft` 等待人工验收（2026-09-01）。

## 1. 概述

`pkg-actor-card/generate/index?cardId=1` 的 MCP 截图显示，Hero 中 `281 x 159rpx` 的个人简介固定卡片直接渲染完整简介。父容器只有 `overflow: hidden`，摘要文本没有行数约束和省略号，长简介会在卡片底部被硬切，最后一行呈现为不完整内容。

本 Spec 将 Hero 中的个人简介明确为三行摘要；长页正文中的“个人简介”继续完整展示原文。修复同时作用于共用 `ActorCardRenderer` 的生成预览和公开页。

## 2. 用户故事

- 作为卡主，我希望 Hero 里的个人简介是完整可读的摘要，不出现半行文字被切断。
- 作为观看者，我希望首屏摘要简洁，同时仍能在长页正文阅读完整个人简介。

## 3. 功能需求

### 3.1 Hero 摘要不硬截断

**验收标准**：

- WHEN 个人简介超过 Hero 固定卡片容量 THEN 文本最多展示三行，并在末尾显示省略语义，不得从卡片底部硬切半行。
- WHEN 个人简介不超过三行 THEN 正常显示原文，不得补虚假内容。
- Hero `intro(81,1077,281,159)` 坐标、尺寸、标题和卡片视觉保持不变。

### 3.2 完整正文保持

**验收标准**：

- 长页正文“个人简介”继续渲染完整 `profile.introduction`，不得复用 Hero 的三行截断样式。
- 统计、基础信息、形象与语言、技能、经历、照片、视频和附件顺序保持不变。

### 3.3 共享页面一致

**验收标准**：

- `generate/index` 与 `view/index` 继续只引用同一个 `ActorCardRenderer`。
- `src`、`dist/build/mp-weixin`、`dist/dev/mp-weixin` 三侧必须包含相同摘要规则，WXML/WXSS/JS scoped hash 一致。
- 微信 MCP 在 `pkg-actor-card/generate/index?cardId=1` 截图确认简介卡不再硬切，控制台无 `error/fail`。

## 4. 非功能需求

- 只使用现有 Design Token 和微信小程序支持的文本截断能力。
- 不改变固定 Hero 画布尺寸，不引入动态高度导致首屏跳动。
- 不新增运行依赖，不扩大分包体积边界。

## 5. 非目标

- 不改个人简介数据来源、接口字段或数据库。
- 不重写个人简介内容，不调用 AI 润色。
- 不调整技能、基础资料、作品、照片或视频模块。
- 不改变下方完整个人简介的内容和排版语义。

## 6. 发布兼容

- 纯前端共享组件样式修复；旧后端响应继续兼容。
- 无数据库迁移、无后端部署依赖。
- 当前 Candidate 在源码变化后失效，必须冻结全新测试 Candidate 并重新通过 build/dev/缓存/实时请求准入。
