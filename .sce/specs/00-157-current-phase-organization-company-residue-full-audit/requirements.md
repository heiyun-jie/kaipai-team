# 00-157 需求

## 目标

全面审查并清理当前框架之外的 `机构/公司/organization/company` 残留，并扩展清理本轮复审暴露的旧域词：`studio`、`membership/member/会员/vip`、`credit/信用/积分`、`fortune/命理`。覆盖：

- 小程序
- 后端 API
- 后台管理
- 数据库脚本/迁移/种子

## 问题

- `pkg-card/actor-card/index` 海报模式仍提示 `海报机构名称缺失`。
- 海报预览仍从 `company` 数据加载名称。
- 上一轮审查只覆盖了卡片模式和局部构建产物，没有覆盖海报模式、后端、后台、数据库，因此审查口径不合格。
- 复审发现后台、小程序、数据库迁移中仍有旧 `studio`、旧会员域和历史权限命名残留，按“有一个残留即不通过”处理。

## 验收标准

- 小程序端不得出现 `海报机构名称缺失`。
- 当前 MVP 分享/海报链路不得依赖 `company` / `机构` 信息。
- 小程序源码和构建产物不得存在当前分享框架外的 `机构` 用户可见文案。
- 后端 API 不得保留当前分享框架外的 `机构/company/organization` 分享链路依赖。
- 后台管理不得展示当前分享框架外的 `机构/company/organization` 分享治理入口。
- 数据库脚本不得保留当前分享框架外的机构依赖字段/种子/迁移入口。
- 当前运行时代码、构建产物、迁移脚本和路径名不得保留上述扩展旧域直连残留。
- 数据库历史清理脚本如必须定位旧线上值，只允许使用拆分动态字符串执行物理清理，不得保留直连旧表名/旧字段/旧文案。
- 审查发现任何未处理残留，本规格不得标记完成。

## 审查评分

- 内部审查必须不低于 95。
- 若发现一个当前框架外残留，直接判定不通过并继续修改。
