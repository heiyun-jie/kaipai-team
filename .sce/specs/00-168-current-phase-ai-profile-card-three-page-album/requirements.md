# AI 分享图固定三页资料册 Requirements

> 状态：已被 `00-171-current-phase-ai-profile-card-single-cover-theme-flow` 取代。旧三页任务不再作为当前目标态，新实现不得继续生成 `cover / resume / gallery` 三页背景图。

## 1. 概述

当前 AI 分享图详情页已经采用“AI 背景图 + 小程序原生前景组件”的确定性渲染方案，但单张 `750 x 1334` 海报只能承载摘要信息。现有页面已经主动压缩内容：基础信息仅展示 4 项、技能仅展示 4 项、照片仅展示 6 张、作品仅展示 1 条、简介仅展示短句。对于资料较完整的演员，单页海报无法同时满足第一屏吸引力和完整资料浏览。

本需求把 AI 分享图从“单张封面图”升级为“固定三页资料册”：

1. 第 1 页 `cover`：封面页，保留当前人物主视觉与核心摘要。
2. 第 2 页 `resume`：履历页，承载完整基础资料、形象标签、语言、技能、简介与作品履历。
3. 第 3 页 `gallery`：影像页，承载分类照片、作品剧照与视频简历入口。

三页都必须继续遵循当前背景图 contract：AI 只生成视觉背景，不负责绘制真实业务文字、资料卡、照片框、视频控件或联系方式。

## 2. 用户故事

### 2.1 演员用户

作为资料较完整的演员，我希望 AI 分享详情页可以展示更多真实资料，而不是把我的履历、照片和技能压缩到一张摘要卡里，这样项目方能更完整地了解我。

### 2.2 项目方浏览者

作为查看分享页的项目方，我希望第一屏先快速判断演员气质，再继续向下浏览履历和影像内容，而不需要跳到多个零散页面。

### 2.3 运营与研发

作为系统维护者，我希望页数固定为 3 页、结构固定、数据可追溯，这样成本、生成时长、页面布局和故障定位都可控。

## 3. 功能需求

### 3.1 固定三页契约

**描述**：新生成的 AI 分享图任务必须固定生成 `cover / resume / gallery` 三页，不支持用户自定义页数，也不支持按资料量动态增减页数。

**验收标准**：

1. WHEN 用户提交一次新的 AI 分享图生成任务 THEN 后端必须创建一个主任务和固定 3 个页面生成目标。
2. WHEN 任一新任务返回给前端 THEN 页面顺序必须稳定为 `cover -> resume -> gallery`。
3. WHEN 后续资料很多 THEN 系统仍必须通过三页内的信息分配与摘要策略承载，而不是生成第 4 页。

### 3.2 三页内容分工

**描述**：每页必须有稳定职责，避免三页都重复展示同一批摘要信息。

**验收标准**：

1. WHEN 渲染 `cover` THEN 页面必须展示人物主视觉、姓名、核心身份摘要、少量事实、少量技能、一个代表作品和短简介。
2. WHEN 渲染 `resume` THEN 页面必须优先承载完整基础资料、形象标签、语言、完整技能组、较完整简介和作品履历。
3. WHEN 渲染 `gallery` THEN 页面必须优先承载头像/形象照/生活照/剧照、作品图像和视频简历入口。
4. WHEN 某类资料缺失 THEN 对应页必须显示确定性空态或降级文案，不得让 AI 伪造文字或内容。

### 3.3 AI 只生成背景

**描述**：三页都沿用背景-only contract，真实资料继续由前端原生组件渲染。

**验收标准**：

1. WHEN 调用任一生图 provider THEN prompt 必须声明当前页是背景图，不允许生成最终文字、标签、资料卡、照片框、二维码、电话或假 UI。
2. WHEN 渲染任一详情页 THEN 用户可见文字、照片、视频入口、联系方式和卡片边框必须由确定性代码渲染。
3. WHEN 用户后续更新个人资料 THEN 详情页必须读取最新资料事实源，不能依赖被烘焙在图片中的旧文字。

### 3.4 统一布局契约

**描述**：三页必须继续使用统一的 `750 x 1334` 设计坐标系，并在 agent、前端和分享图合成逻辑之间保持同源。

**验收标准**：

1. WHEN 生成三页布局元数据 THEN 每页必须包含独立 `pageType`、`designCanvas`、`providerCanvas`、slot 集合和背景留白约束。
2. WHEN 前端渲染三页 THEN 页面必须使用各自 page preset 的 slot，而不是复用一套全局硬编码百分比。
3. WHEN provider 输出高分辨率图片 THEN `2160 x 3840` 只能是输出画布，业务布局的权威坐标仍必须来自 `750 x 1334`。

### 3.5 页面级持久化与可追溯

**描述**：系统必须能识别一次任务下的 3 个页面资产，并支持定位单页失败。

**验收标准**：

1. WHEN 新任务落库 THEN 系统必须能持久化每页的 `pageNo`、`pageType`、prompt、provider、状态和生成图 URL。
2. WHEN `cover` 成功而 `resume` 或 `gallery` 失败 THEN 系统必须能区分失败页，而不是只返回一个笼统任务失败。
3. WHEN 详情页读取任务 THEN 前端必须能拿到有序页面数组，而不是只拿到单个 `generatedImageUrl`。
4. WHEN 旧单页 artifact 被打开 THEN 系统必须继续兼容，不得因多页升级而不可访问。

### 3.6 生成与失败策略

**描述**：固定三页后，系统必须明确任务成功标准和部分失败处理。

**验收标准**：

1. WHEN `cover` 未成功 THEN 整体任务必须失败，因为它是分享入口页。
2. WHEN `cover` 成功但非封面页失败 THEN 第一版默认仍判定整体任务失败，避免用户拿到不完整资料册。
3. WHEN 后续支持单页重试 THEN 重试必须只针对失败页，不得重新生成已经成功且无需变化的页面。
4. WHEN provider 返回原始参考图、mock 图或不可用图片 THEN 对应页面必须失败并保留原因。

### 3.7 详情页体验

**描述**：详情页必须支持自然浏览三页资料册，而不是把三张图塞成不可读的长拼图。

**验收标准**：

1. WHEN 用户打开 AI 详情页 THEN 第一屏仍必须先看到 `cover`。
2. WHEN 用户继续向下滚动 THEN `resume` 和 `gallery` 必须按固定顺序出现。
3. WHEN 页面渲染三页 THEN 底部联系/分享操作栏不能遮挡三页核心内容。
4. WHEN 页面加载图片 THEN 非首屏页必须支持延后加载或等价优化，避免一次性加载 3 张大图拖慢首屏。

### 3.8 分享语义

**描述**：固定三页后，分享链路仍以封面页作为默认入口。

**验收标准**：

1. WHEN 用户点击分享 THEN 默认分享封面仍必须是 `cover` 页。
2. WHEN 外部用户打开分享链接 THEN 必须进入三页详情页，而不是退回单张旧海报页。
3. WHEN 未来支持导出 THEN 三页导出策略必须另行定义，本需求不把三页拼接图作为当前必做项。

### 3.9 成本与配置边界

**描述**：本需求不开放任意页数配置，避免运营侧误把成本和复杂度放大。

**验收标准**：

1. WHEN 后台配置生图 provider THEN 页数不得成为自由输入项；当前能力固定为 3 页。
2. WHEN 估算生成成本 THEN 系统文档必须明确一次完整生成约等于 3 次页面级 provider 调用。
3. WHEN 后续要改变页数 THEN 必须通过新 spec 决策，不得在当前实现中暗留任意页数开关。

## 4. 非功能需求

1. `cover` 首屏性能不得因三页升级明显退化；必须继续复用 display-sized derivative / 延后加载策略。
2. 三页必须保持风格一致，但不要求三页都重复绘制同一位清晰人像。推荐只在 `cover` 使用主肖像，其余页优先使用纯背景。
3. 生成结果必须可审计、可定位、可复现，页面级 prompt 和 provider 结果不能只存在日志中。
4. 当前多 provider 路由能力必须继续生效，三页能力不得绑定到单一厂商。

## 5. 约束条件

1. 不得把真实资料文字交给 AI 绘制。
2. 不得破坏现有普通分享卡、旧单页 AI artifact 和当前作品集入口。
3. 不得把三页页数做成用户可配置或后台任意配置。
4. 不得在本需求中顺手重构非 AI 分享页。
5. 必须承接既有 `00-164`、`00-166`、`00-167` 的确定性布局、设计坐标和首屏性能约束。

## 6. 非目标

1. 本需求不实现 4 页以上资料册。
2. 本需求不实现把三页导出为一张超长拼图。
3. 本需求不要求 AI 在第 2 页、第 3 页继续生成可辨识人物肖像。
4. 本需求不重做演员资料编辑页。
5. 本需求不要求本阶段支持页面拖拽排序或用户自定义模块顺序。

## 7. 验收总则

1. 新任务固定生成三页，顺序稳定。
2. 三页均为背景-only AI 输出，前景资料由前端确定性渲染。
3. 三页各自有 page preset、slot 和页面级资产记录。
4. 旧单页 artifact 可继续打开。
5. 三页详情页真人 E2E 验证通过，且截图覆盖 `cover / resume / gallery`。
