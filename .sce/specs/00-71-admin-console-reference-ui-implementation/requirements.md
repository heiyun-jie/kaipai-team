# 00-71 后台控制台参考稿 UI 落地（Admin Console Reference UI Implementation）

> 状态：进行中 | 优先级：高 | 依赖：00-11 platform-admin-console，00-17 admin-dashboard-hierarchy-optimization，00-18 admin-page-style-alignment
> 记录目的：把用户指定的后台参考稿 `D:\XM\kaipai-team\_-_1.html` 提升为独立 Spec，明确它不是“继续微调旧后台样式”，而是一次面向 `kaipai-admin` 的控制台壳层与工作台重构；同时固化“只承接已有功能，不新增后台业务能力”的边界。

## 1. 背景

当前后台已有两类既有 Spec：

- `00-17`：工作台层级优化
- `00-18`：共享壳层与页面风格统一

但这两者解决的是“基于旧后台视觉继续收敛”，并没有把新的参考稿提升为独立实现边界。用户随后明确要求：

- 参考 `D:\XM\kaipai-team\_-_1.html`
- 对后台 UI 进行修改
- 且“只把已有的功能进行添加进入”

经核对，`_-_1.html` 表达的是一套完整后台控制台视觉稿，重点不只是卡片皮肤，而是：

- 左侧窄导航
- 顶部轻量状态条
- 米白色主画布
- 数据看板式工作台
- 用现有模块组织成控制台信息架构

如果继续把这次修改归入 `00-18`，会出现三个问题：

- 无法区分“共享壳层微调”与“参考稿驱动的控制台重构”
- 无法明确“只挂已有功能，不新增模块”的产品边界
- 后续再继续改后台时，会重新回到“只改局部样式，没有独立 UI 基线”的状态

## 2. 范围

### 2.1 本轮必须处理

- 固化 `D:\XM\kaipai-team\_-_1.html` 为本轮后台控制台 UI 唯一参考基线
- 以 `kaipai-admin` 为唯一实现范围，重做后台公共壳层与工作台页
- 把当前后台**已经存在**的功能入口挂入新的控制台导航
- 保留现有真实路由、权限、接口和页面能力，不允许退回静态原型页
- 为后续剩余后台业务页继续做视觉统一，提供明确边界

### 2.2 本轮不处理

- 新增后台菜单、页面、权限码或后端能力
- 因为参考稿存在而新增“趋势分析/渠道分析”等新业务模块
- 改写现有接口契约、聚合字段或权限模型
- 用静态示意图替换真实后台页面
- 把小程序前台原型实现混入本 Spec

## 3. 需求

### 3.1 参考基线与适用范围

- **R1** `D:\XM\kaipai-team\_-_1.html` 必须被视为当前后台控制台可见层的唯一参考基线；后续同轮后台 UI 调整默认先对齐该文件，而不是继续沿用旧后台页面的历史视觉描述。
- **R2** 本 Spec 只适用于 `D:\XM\kaipai-team\kaipai-admin`，不覆盖小程序前台页面，也不覆盖 `_-_.html` 对应的前台原型实现边界。
- **R3** 本轮必须显式记录：`_-_1.html` 是后台控制台参考稿，不是要直接接入为一个新的后台路由页面。

### 3.2 控制台壳层重构

- **R4** 后台公共壳层必须统一到参考稿的控制台语言：米白背景、窄侧栏、轻量 topbar、圆角浅色内容面板、深浅对比明确的数据卡。
- **R5** 左侧导航必须承接当前后台真实可用模块，禁止为了贴近参考稿而新增不存在的菜单。
- **R6** 左侧导航分组、图标和展开结构可以重排，但底层仍必须来自当前真实菜单 / 路由 / 权限过滤结果。
- **R7** 顶部栏必须保留当前页面标题、账号信息和状态提示语义，但允许按参考稿重排为更轻量的信息条，不再沿用旧“按钮 + 大段运营说明”结构。

### 3.3 只承接已有功能

- **R8** 本轮控制台中可展示的功能入口，必须严格限定为当前 `kaipai-admin/src/router/index.ts` 与 `src/constants/menus.ts` 已存在的页面能力。
- **R9** 不允许因为参考稿出现了看板、分析或内容块，就新增任何当前后台尚不存在的业务页面、假菜单或假入口。
- **R10** 对参考稿中无法直接映射到现有后台能力的部分，只允许作为布局语言参考，不允许被实现成新的产品能力。

### 3.4 工作台页重构

- **R11** 工作台 `kaipai-admin/src/views/dashboard/OverviewView.vue` 必须按参考稿改为数据面板式结构，而不是继续沿用旧版“长文本说明 + 多块业务说明卡”的表达。
- **R12** 工作台允许重组已有数据字段，但只能使用当前真实接口 `/admin/dashboard/overview` 已有的聚合字段与 `recentItems`。
- **R13** 工作台上的指标卡、列表、趋势、分布和入口块，只能由现有字段与现有功能推导得到，不允许引入假数据、伪接口或新统计口径。
- **R14** 当真实接口数据缺失、未返回或本地后端未启动时，页面必须以当前真实空态 / fallback 展示，不得用硬编码成功数据伪装已接通。

### 3.5 业务页视觉 rollout 边界

- **R15** 本轮最低交付范围是：后台公共壳层 + 工作台页完成参考稿对齐。
- **R16** 其他后台业务页在本轮可以继续复用现有组件与共享壳层，不要求一次性全部重写成参考稿结构，但必须显式记录“后续仍可沿新控制台壳层继续统一”。
- **R17** 本轮不允许为了追求全站视觉一致，而破坏现有业务页的字段交互、抽屉、弹窗、表格和高风险操作链路。

### 3.6 治理要求

- **R18** 本轮必须通过独立 `00-71` Spec 固化后台参考稿 UI 落地边界，不能只在聊天里说明“参考某个 html 改后台”。
- **R19** 本轮必须把 `00-71` 挂回 Spec 索引和 Spec↔代码映射表。
- **R20** 本轮必须把已改文件、验证方式和当前不确定边界记录到 `execution.md`，尤其要显式说明真实后端是否参与了联调验证。
