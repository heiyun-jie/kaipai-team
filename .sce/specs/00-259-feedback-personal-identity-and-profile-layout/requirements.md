# 问题反馈：个人身份展示与档案布局

> 状态：本地实现与专项验证完成，待新 Candidate / 真机验收，2026-10-13；2026-10-20 按用户裁决删除完整度与统计区。上游：00-199、00-204、00-225、00-258。

## 1. 问题契约与来源

来源：用户提供的 `问题反馈.xlsx`，Sheet1 A3:AE14，共四张问题/效果截图。本轮用户授权创建 Spec 并修复。
现象：个人页为默认字头像和自动昵称，档案页已有照片；姓名下硬编码“演员”；档案页缺昵称输入，年龄/身高/体重挤在同一行。
期望：个人页显示本人已保存档案头像、可编辑账号昵称，公开名称独立；隐藏姓名下的演员身份标签；测量字段各占一行。
验证：后端昵称兼容测试、前端类型检查、固定 dist/dev 产物与页面回归。运行态截图未采集时不能标成真机已验收。

## 2. 验收标准

### 2.1 头像
- WHEN 已登录进入个人页 THEN 优先用本人档案 avatarAssetId 现签展示，未设置时回退账号头像。
- WHEN 账号切换/退出或旧请求晚到 THEN 不显示上一账号的头像，不对游客发档案或签名请求。
- 临时签名只保存在页面内存，不写入账号持久缓存或数据库。

### 2.2 昵称与公开名称
- WHEN 编辑档案 THEN 头像与公开名称之间有独立“昵称”输入，最多 64 字。
- 昵称归属既有 user.user_name；公开名称仍归属 actor_profile.nick_name；不新增数据列。
- WHEN 保存昵称 THEN 与档案保存同事务，服务端验证非空和长度，个人页缓存同步更新。
- WHEN 旧客户端未传 nickname THEN 不改变账号昵称；旧客户端所有必填字段、乐观锁和身份门禁保持兼容。
- WHEN 更改昵称 THEN 不覆盖公开名称，更改公开名称也不隐式更改昵称。

### 2.3 布局
- 个人页顶部取消单独“演员”徽标，实名认证状态仍由既有事实源显示。
- 年龄、身高、体重各占完整一行，沿用既有字段及岁/cm/kg单位。
- 00-204 同排布局由本需求覆盖，数据模型保持原合同。
- 2026-10-20 用户裁决“直接删除”：个人页不再显示“资料完整度”卡片及“演员卡 / 素材 / 浏览”三项统计；个人页不再请求完整度接口。后端 `/api/actor-card/profile/completeness` 保留不动，供旧版前端兼容。

## 3. 发版兼容

仅向已有档案请求/响应新增可选 nickname，复用已有列，零 DDL/DML 迁移。新前端需要同批次后端；旧前端省略新字段继续可用。代码变化会使旧 Candidate 准入失效，需重冻后再验收；本轮不构成生产发布或体验版上传授权。
