# 技术设计

_Requirements: 2.1-2.6, 3_

## 1. 图片读取边界

- 首图页使用分包内自包含工具 `pkg-actor-card/utils/image-preview.ts`，无业务组件依赖；复用 00-260 已验证的清洗、COS 小缩略图、downloadFile 临时渲染思路。
- URL 清洗保留合法签名查询参数，拒绝非 HTTPS、HTML/跳转后缀；下载日志仅 host/status，不含签名。
- URL 身份与 displayUrl 分离。图库候选缩略 → 原图，各项记录当前显示 URL 与失败候选；error 闭包绑定当次 URL。当前首图 watch 触发准备，使用修订号隔离旧返回；重试素材现签接口沿用 getActorCardMedia。
- 运行验证修正：私有素材绑定与选择页使用同一现签原生图片链路。试验中强制把该链路改为 downloadFile 导致当前素材预览失败/长时间等待，而同一素材在选择页与原生 image 正常；因此不扩大运输层改动，素材绑定保留现签原生渲染，只对模板/历史 URL 下载临时文件。尚未取得失败下载的确切网络原因，不把它归因为域名或签名故障。
- loadBgLibrary 使用独立修订号，切换风格/重试/卸载时失效旧请求；不得只用 finally 覆盖新 loading 状态。
- 模板点击后的大首图优先下载原图；原图下载或解码失败时依次使用图库同图的清洗候选（含缩略图），保存身份仍为原稳定 URL。解码失败回调携带当次修订号与 displayUrl，不能让旧错误影响回退结果；私有素材不改为该运输链路。
- 首页原图回退候选同样清洗，堵住缩略失败后重新请求污染原图的路径；不无关重构首页。

## 2. 首图素材选择

- `step-visual.chooseFromLibrary` 传完整七类照片，默认分类为空；选择页仅 `usage=source_image` 增加“全部照片”，默认不传 categoryCode。
- “全部”是筛选状态，不是素材分类；上传仍落到已有合法分类，不能保存空分类。其他用途仍沿用原默认分类。
- 保留分页、ready/媒体类型检查、单选、会话取消和确认返回语义，不增加平行选择状态。
