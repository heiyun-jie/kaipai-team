# 演员卡结构化长页预览与共享渲染器

> 状态：已完成（2026-08-20）。
>
> 用户裁决：2026-08-20，同意复用公开观看页的数据结构，抽取生成页与公开页共用的结构化演员卡渲染器；海报或长图导出另行处理。

## 1. 概述

`pkg-actor-card/generate/index` 当前把后端返回的 `generatedPreviewUrl` 当成长页图片。后端尚未接入位图长页引擎，只把主视觉原图或扩图写入该字段；前端发现 URL 与主视觉相同后进入“生成任务已完成，但没有完整长页”的占位态。结果是用户完成七步流程后看不到演员卡本体，也无法确认发布内容。

本 Spec 将演员卡正式产物定义为结构化长页：后端使用与公开观看页相同的 `ActorCardPublicRespDTO` 组装草稿预览，前端使用同一个 `ActorCardRenderer` 渲染主视觉、资料、作品、生活照片、视频和附件。生成页与公开页只负责各自的加载、权限、发布和导航状态，不再各自维护一套演员卡正文。

## 2. 用户故事

- 作为演员，我完成创建流程后希望直接看到完整演员卡，而不是“任务完成但没有结果”的提示。
- 作为演员，我希望发布前预览与发布后的公开页结构、顺序和显隐设置一致。
- 作为观看者，我希望本次重构不改变已发布演员卡的可见内容和交互。
- 作为维护者，我希望草稿预览和公开查看复用同一数据组装与渲染模型，避免两套实现继续分叉。

## 3. 功能需求

### 3.1 鉴权草稿预览接口

**验收标准**：

- WHEN 卡主请求 `GET /api/actor-card/draft/{cardId}/preview` THEN 返回与公开页相同结构的 `ActorCardPublicRespDTO`。
- WHEN 草稿属于当前用户 THEN 不要求 `status=published`，允许发布前预览。
- WHEN草稿不存在或不属于当前用户 THEN 返回统一的“演员卡不存在”，不得泄露他人卡片信息。
- 草稿预览与公开查看必须复用同一个组装函数，包括素材绑定签名 URL、作品顺序、设置解析和附件信息。
- 新接口必须鉴权；现有 `/api/actor-card/public/{cardId}` 公开语义不变。

### 3.2 共享结构化渲染器

**验收标准**：

- 新增 `pkg-actor-card/components/ActorCardRenderer.vue`，由 `generate` 与 `view` 两页共同使用。
- 渲染器展示主视觉、个人资料、联系方式、自我介绍、参演作品、生活照片、视频简历和附件简历。
- 模块顺序最初与 `settings.order` 一致；`00-229` 的参考页纠偏已将分享详情覆盖为旧页固定阅读顺序，`showContact/showVideo/showAttachment` 显隐设置继续生效。
- 图片预览、视频播放、附件查看、单资源失败降级保持可用。
- 渲染器必须位于 `pkg-actor-card` 分包并保持业务 API 自包含：只接收展示模型和发出附件预览事件，不直接调用后端接口或主包 store。

### 3.3 生成页完整预览

**验收标准**：

- WHEN生成任务完成 THEN 生成页加载草稿预览接口并展示 `ActorCardRenderer`，不得再比较 `previewUrl === sourceImageUrl/expandedImageUrl` 后进入占位页。
- 页面运行态不得再出现“长页生成引擎暂未提供可展示结果”“当前仅有主视觉占位结果”等文案。
- 发布按钮只在结构化预览加载成功且生成任务完成后可用。
- WHEN从名片夹以 `preview=1` 进入未生成草稿 THEN 先展示结构化预览，并提供“生成演员卡”动作；不得伪装成已生成可发布状态。
- 加载、任务失败、预览接口失败和发布失败必须各自有明确状态和重试路径。

### 3.4 公开页回归

**验收标准**：

- `pkg-actor-card/view/index` 继续校验已发布状态并使用公开接口。
- 公开页导航、加载/404/未发布/网络失败、主视觉、资料、作品、照片、视频和附件行为不回归。
- 公开页与生成页正文必须引用同一个 `ActorCardRenderer`，禁止复制模板形成第二套结构。

## 4. 非功能需求

- 结构化预览首屏不依赖位图长页生成；后端一次返回完整 VO，前端不串行请求多个模块。
- 分包组件不得直接 import `@/api/*`、Pinia store 或主包业务组件。
- `src`、`dist/build/mp-weixin`、`dist/dev/mp-weixin` 三侧必须存在共享组件引用，且 build/dev scope hash 一致。
- 微信运行态至少验证：生成页完整正文、滚动、发布按钮；公开页正文；生活照片三列；附件入口。

## 5. 非目标

- 不在本 Spec 生成分享海报、整页截图、PDF 或单张超长位图。
- 不修改演员卡字段、素材绑定表、数据库结构或历史数据。
- 不删除旧生成接口和 `generatedPreviewUrl` 字段；它们继续为旧客户端与当前发布门禁提供兼容。
- 不在本次重新设计演员卡视觉主题，只收口数据与共享渲染结构。

## 6. 发布兼容

- 后端新增接口和服务方法，不修改现有请求/响应，旧前端继续可用。
- 新前端依赖新增草稿预览接口，前后端必须同批发布；先发布后端对旧前端无影响。
- 数据库零变化，无迁移、seed 或数据回填。
- 回退新前端后，旧 `generatedPreviewUrl` 链路仍在；回退后端前必须先回退新前端。
