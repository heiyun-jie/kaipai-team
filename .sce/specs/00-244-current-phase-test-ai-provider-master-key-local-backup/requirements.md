# 测试环境 AI Provider 主密钥本地备份与隔离使用

## 1. 概述

为测试环境的 AI 演员卡扩图提供已存在的运行时加密主密钥副本，同时保持生产容器、生产配置和生产数据库不变。

## 2. 用户故事

作为测试验收人员，我希望测试后端可以解密测试数据库中的 AI provider 配置，继续验证扩图流程。

作为发布操作人，我希望主密钥只落在本地 gitignored 密钥文件和测试运行时，任何生产服务状态都不被改变。

## 3. 功能需求

### 3.1 只读来源

- WHEN 读取主密钥 THEN 来源只能是当前线上运行配置的 `AI_PROVIDER_CONFIG_MASTER_KEY`，不得读取或修改生产数据库数据。
- 密钥值不得输出到终端、日志、Spec、截图、Git 或 HTTP 响应。

### 3.2 本地备份

- 本地文件固定为 `.sce/config/local-secrets/ai-provider-runtime.env`。
- 文件权限为仅当前用户可读写；文件内容只包含主密钥变量。
- 文件必须被 Git 忽略，且验证记录只保存长度、SHA256 和存在性。

### 3.3 测试隔离

- 测试环境可使用本地备份值同步到 `kaipai-backend-test` 的 secret env。
- 不得修改 `kaipai-backend` 生产容器、生产 compose、生产 Nginx、生产数据库或生产 provider 配置。
- 测试数据库继续使用 `kaipai_test`，Redis 继续使用 DB `1`。

### 3.4 可回滚

- 同步前备份测试 secret env。
- 回滚只恢复测试环境备份，生产运行态保持原值。

## 4. 验收标准

- 本地主密钥文件存在且权限正确，值不出现在验证输出。
- 测试运行时读取主密钥后不再返回“主密钥未配置”。
- 生产容器 ID、启动时间和重启次数与操作前一致。
- 测试 API 保持可用，测试数据库/Redis 目标不变。
- 全部证据不包含密钥明文。

## 5. 约束条件

- 本 Spec 不授权生产发布或生产配置变更。
- 仅使用测试环境专用执行入口；任何测试环境重建都必须留备份和回滚记录。
