# scoped 哈希分叉深度调查与根治（第 6 次复发）

## 1. 概述

本 Spec 深度调查「微信开发者工具把 `dist/dev` 的 wxss/js 写回旧 scopeId → scoped 哈希分叉 → 样式静默失效」问题（累计第 6 次出现），推翻此前所有「假设-修复」轮次（重同步/退工具/清缓存/关 es6），**以实验证据定位写回机制并给出可验证的根治方案**。

**历史轮次**（此前 5 次的处置均未根除）：
- 00-212 四之四：sync 脚本时间戳 → `/IS /IT` + 哈希断言
- 第 2 次：工具运行态写回 → 重同步
- 第 3 次：19 文件分叉 → 断言增强（含 js）+ 提示关工具
- 第 4 次：`cli quit` 完全退出 + `cache --clean all` → 仍复发
- 第 5 次：假设 `es6:true` 转换写回 → 关 es6 + `Set-DevCompileSettings` → **仍复发**（本 Spec 触发）

## 2. 已采集证据（2026-08-14 深度调查）

| # | 证据 | 结论 |
|---|------|------|
| E1 | `dist/build` 三件套恒一致（0 分叉） | 构建产物无问题 |
| E2 | dev 分叉文件 wxss/js 与 build **逻辑内容相同、字节长度相同**，唯一差异是 scopeId（dev=`961980b7`，build=`f661c11f`） | dev 文件 = 「当前逻辑 + 另一个 scopeId」，**不是旧逻辑** |
| E3 | 重新构建后 build scopeId **稳定不变**（`f661c11f`） | scopeId 是内容函数，`961980b7` **不是 npm 构建产物** |
| E4 | dev 分叉文件时间戳 = sync 后 **26 秒**（12:01:30 → 12:01:56），工具当时在运行 | **工具在 sync 后立即写回** |
| E5 | 搜索 `APPDATA/LOCALAPPDATA/微信开发者工具` 缓存，**无 961980b7 文本** | 工具缓存不在常规文本文件，或为二进制/LevelDB |
| E6 | 关 `es6` 后 120 秒稳定，但长时间使用仍复发 | es6 转换是写回的**部分/触发**，不是根因；工具另有编译写回机制 |

**核心矛盾**：scopeId 稳定（E3）+ dev 是「当前逻辑 + 旧 scopeId」（E2）→ 工具写回的版本**无法由 npm 构建产生** → 工具的编译缓存持有「以旧 scopeId 为键/内容的当前逻辑」版本。

## 3. 深度调查实验（tasks T2-T5）

### T2 定位工具编译缓存
- 目标：找到工具的编译缓存（LevelDB / IndexedDB / 项目级缓存目录），确认其中含旧 scopeId 版本
- 手段：列出 `User Data/<hash>` 下全部子目录与大小；搜索二进制文件内 961980b7（`findstr`/strings）

### T3 写回触发实验（决定性）
- 步骤：清工具全部缓存 → `open`（工具基于当前 dev 编译）→ 记录 dev scopeId → **保持工具打开** → 修改一个源文件 → `build` + `sync` → **秒级监控** dev 分叉文件的写入（时间戳/内容）
- 判读：若写回「新版本」（一致）→ 缓存更新机制正常，清缓存根治；若写回「旧 scopeId」→ 工具缓存机制更深，需方案 D

### T4 工具编译行为配置调查
- 微信开发者工具设置项：`project.config.json`（es6/postcss/minified）、`project.private.config.json`、工具「详情→本地设置」、`compileType`
- 目标：找出可关闭「写回」的开关，或确认工具对已编译产物项目的编译策略

### T5 根治方案验证
- 候选：
  - A. 清缓存 + 确认缓存更新（若 T3 写回新版本）
  - B. 工具缓存目录**只读/清除**（若 T3 写回旧版本）
  - C. 构建后**自动重开工具**（sync 后 open，工具以新文件为基准编译，写回即新版本）
  - D. 最后兜底：**watch 守护**（构建后/工具写回后自动检测修复）
