# 00-174 当前阶段登录页验证码审核门禁

## 1. 概述

当前微信手机号一键登录已经进入可用链路，但手机号验证码登录仍处于审核前状态。登录页继续展示手机号输入、验证码输入、获取验证码和登录 / 注册按钮，会让审核前不可用能力暴露给用户。

本 Spec 负责把 `pages/login/index` 在当前阶段收口为“只展示微信一键登录”的审核态页面。手机号验证码登录代码可以保留，但在验证码能力审核通过前不得在页面运行态渲染。

## 2. 用户故事

作为小程序用户，我进入登录页时只看到当前可用的微信一键登录，不会被引导去使用尚未审核通过的验证码能力。

作为产品 / 运营人员，我希望验证码登录能力可以在审核通过后按独立开关恢复，而不是本轮直接删除短信登录代码。

## 3. 功能需求

### 3.1 隐藏验证码登录表单

**描述**：`pages/login/index` 当前阶段不得渲染手机号输入、验证码输入、获取验证码按钮和“登录 / 注册”短信提交按钮。

**验收标准**：

- WHEN 用户打开 `pages/login/index` THEN 页面不展示手机号输入框。
- WHEN 用户打开 `pages/login/index` THEN 页面不展示验证码输入框与获取验证码动作。
- WHEN 用户打开 `pages/login/index` THEN 页面不展示短信登录 / 注册提交按钮。
- WHEN 构建 `mp-weixin` 产物 THEN 生成的登录页 WXML 不应包含验证码登录表单对应的可见文本。

### 3.2 只保留微信一键登录

**描述**：登录页主操作只保留微信一键登录。用户勾选协议后，微信按钮继续通过 `open-type="getPhoneNumber"` 触发手机号授权。

**验收标准**：

- WHEN 微信登录运行时配置可用且用户已勾选协议 THEN 微信按钮挂载 `getPhoneNumber` 授权能力。
- WHEN 用户未勾选协议 THEN 点击微信登录不直接触发授权，应先提示确认协议。
- WHEN 微信返回手机号授权 code THEN 前端继续复用 `00-173` 的 `/api/auth/wechat-login` 请求合同。

### 3.3 审核态登录页视觉收口

**描述**：验证码登录表单隐藏后，登录页不得保留原短信表单高度造成的下半屏空白；页面底部应由当前登录卡片或非交互视觉元素自然承接。

**验收标准**：

- WHEN 用户在 iPhone 12/13 等常见预览尺寸打开登录页 THEN 微信一键登录卡片下方不出现大面积空白区域。
- WHEN 登录页仅开放微信一键登录 THEN 页面底部只能补充非交互视觉元素，不得新增验证码登录、手机号输入或其他审核前不可用入口。
- WHEN 构建 `mp-weixin` 产物 THEN 登录页仍不包含短信登录表单对应的可见文本。

### 3.4 保留短信登录代码但不开放运行态入口

**描述**：本轮不删除短信登录、注册、发送验证码相关函数和 API 调用，只通过显式审核门禁让它们退出页面可见层。

**验收标准**：

- WHEN 后续验证码审核通过 THEN 可以通过单独 Spec 或显式开关恢复短信登录表单。
- WHEN 当前阶段构建小程序 THEN `sendCode / loginByPhone / registerByPhone` 不应由登录页可见控件触发。
- WHEN 本轮修改完成 THEN 不改后端短信接口、不改数据库、不引入 mock。

## 4. 非功能需求

- 不提交微信 `appSecret`。
- 不新增前端 mock 登录。
- 不删除 `00-173` 已打通的微信一键登录链路。
- 不改变登录成功后的用户态写入和跳转规则。

## 5. 约束条件

- 本轮只处理 `kaipai-frontend/src/pages/login/index.vue` 的登录页展示门禁与必要文案。
- 手机号验证码能力审核通过前，不能把短信登录入口重新暴露到小程序运行态。
- 登录页视觉填充只能使用当前品牌/影像语义的非交互元素，不得用审核前不可用能力填充空白。
