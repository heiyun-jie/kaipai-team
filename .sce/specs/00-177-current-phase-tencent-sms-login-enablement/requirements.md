# 00-177 当前阶段腾讯云短信验证码登录启用

## 1. 概述

`00-51` 已把正式短信能力降级为后续批次，`00-174` 在验证码能力审核前把 `pages/login/index` 的手机号验证码登录表单隐藏。现在用户明确要求“对接手机验证码登录，可以把之前隐藏掉的手机号登录放出来”。

本 Spec 负责把手机号验证码登录从开发态直返验证码推进到生产可接腾讯云 SMS 的后端通道，并恢复登录页手机号验证码入口。微信一键登录继续保留，不在本轮删除。

## 2. 用户故事

作为小程序用户，我希望可以输入手机号、获取短信验证码，并完成登录或自动注册。

作为平台维护者，我希望验证码由腾讯云 SMS 发送，生产态不再把验证码直接返回给前端。

作为开发者，我希望在腾讯云配置未就绪时，接口给出明确错误，不静默伪造“发送成功”。

## 3. 功能需求

### 3.1 腾讯云 SMS 发送通道

**描述**：后端 `/api/auth/sendCode` 生成 6 位验证码后，通过腾讯云 SMS `SendSms` API 发送验证码。

**验收标准**：

- WHEN `kaipai.sms.provider-code=tencent` 且腾讯云配置完整 THEN `/api/auth/sendCode` 调用腾讯云 SMS。
- WHEN 腾讯云返回成功 THEN Redis 保存验证码，TTL 维持 10 分钟。
- WHEN 腾讯云返回失败或 HTTP 异常 THEN 本次 Redis 验证码不得保留，并返回明确业务错误。
- WHEN 腾讯云配置缺失 THEN 返回“腾讯云短信配置未完成”，不得假装发送成功。

### 3.2 开发通道隔离

**描述**：保留本地开发直返验证码能力，但只能通过显式 `kaipai.sms.provider-code=dev` 启用；默认配置走腾讯云。

**验收标准**：

- WHEN `kaipai.sms.provider-code=dev` THEN `/api/auth/sendCode` 可继续返回验证码用于本地开发。
- WHEN `kaipai.sms.provider-code=tencent` THEN `/api/auth/sendCode` 的 `data` 不返回验证码。
- WHEN 未配置 provider THEN 默认按 `tencent` 处理。

### 3.3 登录页短信入口恢复

**描述**：恢复 `pages/login/index` 中手机号输入、验证码输入、获取验证码按钮和“登录 / 注册”主操作；微信一键登录作为次级入口保留。

**验收标准**：

- WHEN 用户打开登录页 THEN 可见手机号输入框。
- WHEN 用户打开登录页 THEN 可见验证码输入框和获取验证码按钮。
- WHEN 用户输入合法手机号 THEN 可以点击获取验证码。
- WHEN 用户输入验证码并勾选协议 THEN 可以点击“登录 / 注册”。
- WHEN 手机号未注册且验证码正确 THEN 沿用既有自动注册逻辑。
- WHEN 微信登录配置可用 THEN 微信一键登录仍可使用。

### 3.4 前端生产态文案

**描述**：生产态验证码发送成功后不展示验证码内容，只展示“验证码已发送”。

**验收标准**：

- WHEN `sendCode` 返回空 data THEN 前端提示“验证码已发送”。
- WHEN dev provider 返回验证码 THEN 前端仍可展示验证码，方便本地开发。
- WHEN 发送失败 THEN 前端展示后端错误消息。

### 3.5 配置与安全

**描述**：腾讯云密钥只由后端配置承接，不进入前端、不写入仓库、不落日志。

**验收标准**：

- WHEN 查看前端代码 THEN 不存在腾讯云 `SecretId / SecretKey`。
- WHEN 查看日志策略 THEN 不记录完整手机号和验证码。
- WHEN 查看配置 THEN 腾讯云配置来自环境变量 / Nacos。

## 4. 非功能需求

- 不接入腾讯云实名认证，本轮只处理 SMS 验证码登录。
- 不新增数据库表；短信发送日志和频控治理留到后续独立 Spec。
- 不改微信手机号一键登录链路。
- 不提交任何真实腾讯云密钥。
- 保持 Redis 验证码 10 分钟有效期和登录 / 注册消费后删除逻辑。

## 5. 约束条件

- 后端 API 仍为 `/api/auth/sendCode`、`/api/auth/login`、`/api/auth/register`。
- 腾讯云短信模板必须在控制台审核通过后才能真实发送。
- `PhoneNumberSet` 使用中国大陆手机号 E.164 格式：`+86{phone}`。
- 登录页恢复短信入口后，必须重新执行小程序构建和包体审计。
