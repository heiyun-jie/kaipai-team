# 00-189 当前阶段小程序全量 E2E 截图与文档整理审计

## 1. 概述

`00-187 / 00-188` 已针对 `2026-07-01` 微信小程序「开拍了演员卡」拒审反馈完成登录门禁与复审合规专项整改。本轮目标是启动微信开发者工具，基于固定运行目录 `kaipai-frontend/dist/dev/mp-weixin` 做一次全页面运行态截图、业务流程 E2E 复核和旧文档整理。

本轮不以修改业务功能为默认目标；若 E2E 发现阻断问题，应先记录证据、归类到页面 / 流程 / 文档矩阵，再按 SCE 另起修复任务或在本 Spec 内补小范围修复任务。

## 2. 用户故事

作为开发者，我希望微信开发者工具打开的是最新 `dist/dev/mp-weixin`，避免看到旧页面或错误工作区。

作为审核准备人员，我希望每个小程序页面都有一张当前运行态截图，用来判断复审包是否能完整体验。

作为产品和工程负责人，我希望业务流程被重新梳理，确认首页游客态、登录、实名、创建分享页、AI 分享图、作品集、分享预览、历史、我的、协议设置等主链路是否仍符合当前产品状态。

作为文档维护者，我希望旧文档中的过期页面、旧主线、旧截图和旧流程描述被集中盘点，避免后续继续引用已退场能力。

## 3. 功能需求

### 3.1 启动微信小程序运行态

**描述**：必须通过微信开发者工具打开固定工程目录 `kaipai-frontend/dist/dev/mp-weixin`，并记录登录态、工程路径和模拟器加载状态。

**验收标准**：

- WHEN 启动微信开发者工具 THEN `ProjectPath` 指向 `kaipai-frontend/dist/dev/mp-weixin`。
- WHEN CLI 可查询登录态 THEN 记录 `islogin` 结果。
- WHEN 检查最近 WeappLog THEN 能看到当前工程路径或模拟器 ready 证据；若无法获取则记录缺口。
- WHEN 后续 E2E 使用 automator THEN automator 连接端口和工具路径写入执行记录。

### 3.2 每个页面必须截图

**描述**：以 `dist/dev/mp-weixin/app.json` 为运行态页面清单，对主包页面与分包页面逐一截图。截图失败不得静默跳过，必须在 manifest 中记录失败原因。

**验收标准**：

- WHEN 读取 `app.json.pages` THEN 主包 15 个页面都进入截图目标。
- WHEN 读取 `app.json.subPackages` THEN `pkg-card` 10 个页面与 `pkg-tools` 2 个页面都进入截图目标。
- WHEN 页面需要登录态 THEN E2E 注入测试登录态后截图。
- WHEN 页面适合游客态 THEN E2E 清空 session 后截图。
- WHEN 页面需要参数 THEN 使用当前可构造的最小参数截图；若缺少真实业务 ID，应记录参数缺口并保留截图失败证据。
- WHEN 截图完成 THEN 生成截图目录、页面数据快照和 manifest。

### 3.3 业务流程重新梳理

**描述**：必须重新梳理当前小程序前台业务流程，至少覆盖游客浏览、登录、演员档案、实名、创建分享页、AI 分享图、作品集 / 已创建分享、分享预览、公开详情、历史记录、我的页、协议 / 设置 / 视频指南。

**验收标准**：

- WHEN 流程有自动化条件 THEN E2E 脚本执行关键路径并截图关键节点。
- WHEN 流程依赖后端真实数据或登录态 THEN 记录使用的测试账号、接口基址和注入方式。
- WHEN 流程因数据缺失、后端异常或页面缺参无法完整闭环 THEN 记录为阻断项，不伪造通过。
- WHEN 流程梳理完成 THEN 生成流程矩阵文档，包含入口、前置条件、关键页面、预期结果、截图证据和问题。

### 3.4 旧文档重新整理

**描述**：盘点旧文档和历史 Spec 中与小程序当前运行态冲突的内容，明确保留、更新、归档或后续修复策略。

**验收标准**：

- WHEN 扫描 docs 与 `.sce/specs` 中的小程序文档 THEN 识别旧主线、旧页面、旧截图、旧流程和旧能力描述。
- WHEN 文档仍有效 THEN 标记为保留。
- WHEN 文档与当前运行态冲突 THEN 标记为需更新或历史归档。
- WHEN 文档整理完成 THEN 生成旧文档整理矩阵，避免直接大范围重写历史记录。

### 3.5 执行记录回填

**描述**：本轮必须把启动结果、E2E 结果、截图 manifest、流程矩阵和旧文档整理矩阵回填到 `00-189`。

**验收标准**：

- WHEN E2E 完成或部分失败 THEN `execution.md` 写明命令、结果、失败项和证据路径。
- WHEN 截图完成 THEN `execution.md` 链接截图目录和 manifest。
- WHEN 文档整理完成 THEN `execution.md` 链接流程矩阵与旧文档矩阵。
- WHEN 验证完成 THEN 更新 `.sce/specs/README.md` 与 `spec-code-mapping.md`。

## 4. 非功能需求

- 不修改 appid、secret、私有配置或微信后台配置。
- 不把截图和大体积样本提交到根仓跟踪区；样本应进入已 gitignore 的 `output/` 或对应 Spec 的 samples 目录。
- 自动化应优先复用已有 `miniprogram-automator`，避免引入新依赖。
- 截图和流程结果必须区分成功、失败和跳过，不允许只输出成功页。
- 若微信开发者工具未登录、未开启 CLI/自动化能力或 automator 无法连接，应记录为环境阻断并继续完成可静态梳理的文档矩阵。

## 5. 约束条件

- 微信开发者工具固定打开 `kaipai-frontend/dist/dev/mp-weixin`。
- 构建产物基线来自 `npm run build:mp-weixin` 的 postbuild 同步结果。
- 页面清单以 `dist/dev/mp-weixin/app.json` 为准，不以旧文档统计为准。
- 当前小程序前台历史主线可追溯到 `00-27 / 00-28 / 05-05 / 05-09 / 05-10 / 05-12 / 05-13 / 05-15 / 05-19 / 00-187 / 00-188`，但不得把已退场的 `fortune` 等旧能力重新作为当前运行态要求。
