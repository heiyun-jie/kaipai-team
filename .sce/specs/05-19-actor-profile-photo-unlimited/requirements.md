# 演员档案个人照片无限制上传 Requirements

> 状态：当前执行中 | 优先级：高 | 依赖：05-02、05-15、05-16

## 1. 概述

当前演员档案编辑页的“个人照片”模块仍沿用 `05-02` 的旧限制：三类照片每类最多 3 张，总计最多 9 张。用户最新要求取消个人照片数量限制，即：

- “形象照 / 生活照 / 剧照”每类不再限制 3 张。
- “个人照片”总数不再限制 9 张。
- 达到 3 张后仍然可以继续添加。

本需求只取消演员档案照片池的上传和展示上限，不取消分享卡片版式内“最多选择 3 张作品”的展示选择限制。

## 2. 用户故事

- 作为演员，我希望个人档案可以持续上传更多形象照、生活照和剧照，不被每类 3 张卡住。
- 作为演员，我希望已上传数量只显示当前张数，不再显示 `3/3`、`9/9` 这种上限状态。
- 作为研发，我希望编辑页、AI 分析图同步档案、作品上传入口和作品集展示都不再把档案照片截断为 9 张。

## 3. 功能需求

### 3.1 编辑页个人照片取消数量上限

**描述**：`pages/actor-profile/edit` 的 `个人照片 / PHOTO GALLERY` 模块取消每类 3 张和总计 9 张限制。

**验收标准**：

1. WHEN 某一分类已有 3 张或更多照片 THEN 添加入口仍然显示。
2. WHEN 用户继续添加照片 THEN 前端不因 `length >= 3` 提前返回。
3. WHEN 用户一次选择多张图片 THEN 本次选择的图片全部按顺序上传到当前分类，不因分类已有 3 张而中断。
4. WHEN 页面展示总数 THEN 显示 `已上传 N 张`，不显示 `N/9`。
5. WHEN 分类展示数量 THEN 显示 `N 张`，不显示 `N/3`。

### 3.2 档案照片读取和保存不截断

**描述**：`photoCategories` 和兼容字段 `photos` 在前端归一化、合并、保存时不再截断为 9 张或每类 3 张。

**验收标准**：

1. WHEN 后端返回 `photoCategories.portrait` 超过 3 张 THEN 编辑页保留完整数组。
2. WHEN 后端返回总照片超过 9 张 THEN `photos` 合并结果保留完整数组。
3. WHEN 保存档案 THEN payload 中 `photos` 和 `photoCategories` 保留完整照片集合。

### 3.3 关联入口同步取消档案照片池上限

**描述**：AI 分析图同步档案、卡片创建页上传作品、作品集展示等消费演员档案照片池的入口，不得继续把档案照片池截断为每类 3 张或总计 9 张。

**验收标准**：

1. WHEN AI 分析图上传后写入档案照片池 THEN 不因形象照已有 3 张而覆盖或丢弃旧照片。
2. WHEN 卡片创建页上传作品图写入档案照片池 THEN 不因总数已有 9 张而阻止上传。
3. WHEN 作品集展示照片分组 THEN 展示当前实际张数，不显示 `/9` 或 `/3`。

### 3.4 分享卡片选图限制保留

**描述**：取消的是档案照片池上传上限，不是分享卡片版式选图上限。

**验收标准**：

1. WHEN 用户为单张分享卡选择代表作品 THEN `MAX_SELECTED_WORK_PHOTOS = 3` 仍然保留。
2. WHEN 卡片配置保存 `highlightedPhotos` THEN 仍只保存当前版式允许的代表图数量。

## 4. 非功能需求

1. 不修改后端接口合同，继续使用 `ActorProfile.photos` 和 `ActorProfile.photoCategories`。
2. 不改变图片单文件大小限制，`photo` 类型仍沿用 05-16 的 10MB。
3. 不引入分页、拖拽排序或批量管理，本轮只取消数量上限。
4. 小程序构建产物必须同步到 `dist/dev/mp-weixin`。

## 5. 约束条件

1. 不改头像、视频、PDF、拍摄经历剧照的数量限制。
2. 不改分享卡片已选作品的 3 张版式限制。
3. 旧 `photos` 扁平数组没有分类信息时，前 3 张继续映射到形象照，4-6 张映射到生活照，其余映射到剧照，避免旧数据迁移时丢图。

## 6. 验收总则

1. 编辑页个人照片模块不再出现 `9/9` 或 `3/3`。
2. 用户在任一分类达到 3 张后仍可继续添加照片。
3. 前端归一化和保存不再截断照片数组。
4. 类型检查和微信小程序构建通过。
