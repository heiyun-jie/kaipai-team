# 00-185 当前阶段同机测试 / 生产双环境治理

## 1. 概述

当前准备发布生产环境，同时要求保留测试环境。由于后端已支持 `SPRING_PROFILES_ACTIVE` 与 `NACOS_ENABLED` 做环境切换，最小可行方案是在同一台服务器上建立两套独立运行时：生产环境承接正式域名，测试环境使用测试域名、独立容器、独立端口、独立 Nacos dataId、独立数据库 / Redis 逻辑隔离。

本 Spec 负责固化同机双环境目标架构、命名规则、发布顺序、验证门禁与回滚边界。本轮只记录治理方案与运维流程，不实际修改远端服务器。

## 2. 用户故事

作为发布操作人，我希望能把最新版本发布到生产环境，同时保留测试环境继续验证下一批功能。

作为维护者，我希望测试环境和生产环境不会共用 Nacos dataId、数据库、Redis、容器或域名，避免测试数据污染生产。

作为项目负责人，我希望生产发布前必须先确认测试环境仍可用，生产发布后必须能通过正式公网域名验证。

## 3. 功能需求

### 3.1 建立同机双环境目标拓扑

**描述**：在同一台服务器 `101.43.57.62` 上，测试与生产必须具备独立运行时边界。

**验收标准**：

- WHEN 查看目标拓扑 THEN 生产环境使用 `api.kplyyk.com / kplyyk.com`。
- WHEN 查看目标拓扑 THEN 测试环境使用 `test-api.kplyyk.com / test.kplyyk.com`。
- WHEN 查看后端容器 THEN 测试与生产容器名不同。
- WHEN 查看后端端口 THEN 测试与生产端口不同。
- WHEN 查看 Nacos THEN 测试与生产 dataId 不同。
- WHEN 查看数据库 THEN 测试与生产数据库或 schema 不同。

### 3.2 明确测试环境保留顺序

**描述**：正式切换生产前，必须先让测试环境以独立地址可访问，避免把现有可验证环境直接覆盖成生产。

**验收标准**：

- WHEN 生产发布前 THEN 必须先完成测试环境 smoke。
- WHEN 测试环境不可访问 THEN 不允许继续生产切换。
- WHEN 测试环境可访问 THEN 继续切换生产环境。

### 3.3 明确生产发布顺序

**描述**：生产环境发布必须在测试环境保留后执行，并按 Nacos、compose/env、后端发布、管理端发布、smoke 的顺序推进。

**验收标准**：

- WHEN 发布生产后端 THEN 远端生产容器必须回读 `SPRING_PROFILES_ACTIVE=prod`、`NACOS_ENABLED=true`。
- WHEN 发布生产后端 THEN 使用 `kaipai-backend-prod.yml`。
- WHEN 发布生产管理端 THEN 使用 `https://kplyyk.com` 做公网 smoke。
- WHEN 任一生产 smoke 失败 THEN 本轮必须中止或回滚。

### 3.4 发布记录分环境留档

**描述**：测试与生产发布记录必须分开命名和留档。

**验收标准**：

- WHEN 测试环境发布 THEN 记录名包含 `test`。
- WHEN 生产环境发布 THEN 记录名包含 `prod`。
- WHEN 生产发布记录完成 THEN 包含测试环境保留验证结果。

## 4. 非功能需求

- 不新增明文密钥到仓库。
- 不把 `prod` 写死进源码。
- 不让测试和生产共用数据库写入目标。
- 不让测试流量走正式生产域名。

## 5. 约束条件

- 本轮不执行真实生产发布。
- 本轮不修改远端服务器、不改 Nacos 内容、不改 Nginx。
- 若后续执行落地，必须先备份远端 compose、Nginx 和当前运行 JAR。
