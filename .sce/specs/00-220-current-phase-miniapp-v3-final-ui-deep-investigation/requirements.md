# 3.0 小程序最终 UI 与操作体系深度调查

> 状态：调查完成，实施未开始。
> 触发需求：当前运行版本为 1.0，已有一套自行开发的 2.0 UI；现需以本地视觉参考为基准，调查 3.0 最终 UI 尚未收口的页面、主题色和操作能力，并为后续实现建立唯一合同。
> 视觉基准：`C:\Users\33340\Desktop\开拍了\小程序UI图`。

## 1. 调查目标

本 Spec 不直接修改页面代码，而是回答以下问题：

1. 当前 `pages.json` 真实注册了哪些页面，文档登记是否一致。
2. 五张 2.0 参考图对应的页面，哪些只是结构接近，哪些交互仍未实现。
3. 其余页面、共享组件、Design Token 和 TabBar 图标中，哪些仍保留 1.0 棕米色 / 橙色主题。
4. 3.0 最终版需要统一哪些导航、主题、状态、空态、按钮和操作契约。
5. 哪些问题属于 UI 改造，哪些问题属于操作能力或后端合同，避免只换色而留下死链和假操作。

## 2. 用户故事

- 作为演员，我希望整个小程序无论从哪个入口进入，都使用同一套最终视觉语言，不再出现蓝白新页、棕米色旧页和橙色 Tab 图标并存。
- 作为演员，我希望参考图中的按钮、列表、上传、排序、继续编辑和导航操作都能真实完成，而不是点击后无反应或只提示“即将开放”。
- 作为产品维护者，我希望 3.0 的页面清单、主题 Token、组件契约和操作验收可以追溯到源码、产物和视觉参考。

## 3. 调查范围

### 3.1 纳入范围

- 小程序 `kaipai-frontend/src/pages.json` 中登记的全部页面。
- 五张参考图：`01-新版首页.png`、`02-AI创建流程.png`、`03-参演作品.png`、`04-生活照片.png`、`05-个人中心.png`。
- `src/styles/_tokens.scss`、`_mixins.scss`、`_page-layout.scss`、`_reset.scss`。
- `src/components/Kp*.vue` 共享组件和 `src/static/tabbar/*` TabBar 图标。
- 既有 2.0 合同与治理：`00-206`、`00-210`、`00-212`、`00-213`、`00-214`、`00-215`、`00-218`、`00-219`。
- 当前页面源码中的可达性、点击行为、上传、排序、预览、删除、发布和跳转逻辑。

### 3.2 不纳入本轮实施

- 不修改任何 `.vue`、`.ts`、`.scss`、后端 Java 或数据库迁移。
- 不删除旧路由或历史分享页；其是否退场在后续产品裁决后处理。
- 不宣称当前运行态已完成 3.0，也不以构建成功替代视觉验收。

## 4. 真实路由基线

调查以 `pages.json` 为唯一权威，当前实际注册数量为 **22 页**：主包 6 页，`pkg-actor-card` 10 页，`pkg-card` 2 页，`pkg-tools` 2 页，`pkg-profile` 2 页。

现有 `CURRENT_CONTEXT.md`、`docs/product-design.md`、`spec-code-mapping.md` 仍写 20 页 / `pkg-actor-card` 9 页；这是 00-215、00-217 增加观看者页和恢复历史分享页后的文档漂移，必须在 3.0 实施前统一。

## 5. 功能需求与验收标准

### 5.1 页面清单与完成度调查

**WHEN** 调查完成 **THEN** 必须为 22 个路由逐项记录：源码路径、分包、当前主题、是否有参考图、UI 完成度、操作风险、3.0 优先级。

### 5.2 参考图对照调查

**WHEN** 对照五张参考图 **THEN** 必须区分“视觉结构已接近”和“交互合同已闭合”，不能仅依据 class 或颜色存在宣称完成。

至少核对：

- 首页 Hero、草稿续编、模板风格 Tab、模板网格和四项 TabBar。
- 创建 Hub 的 7 步状态、进度、跳转和底部主操作。
- 参演作品的经历选择、新增作品、剧照封面、添加与管理操作。
- 生活照片的素材库选择、手机上传、数量提示、删除、排序和下一步。
- 个人中心的头像资料卡、完整度、统计、资料分组、服务分组和 TabBar。

### 5.3 最终主题调查

**WHEN** 页面进入 3.0 实施 **THEN** 所有用户可达页面与共享组件必须使用统一蓝白主题 Token，不得再依赖旧棕米色 Token 或橙色位图作为选中态。

目标色板以参考图与现有 2.0 蓝白页面的交集为基线：

| Token | 目标值 | 用途 |
|---|---|---|
| `brand` | `#2F6BFF` | 主按钮、选中态、进度、链接 |
| `brand-soft` | `#EEF2FF` | 浅蓝背景、选中容器、提示 |
| `canvas` | `#FFFFFF` | 页面主背景 |
| `surface-muted` | `#F6F7F9` | 分组背景、列表页底色 |
| `text-primary` | `#171A21` | 标题和主文字 |
| `text-secondary` | `#667080` | 描述与辅助文字 |
| `text-tertiary` | `#8E8E93` | 次要状态和占位 |
| `border` | `#E8E8E8` | 卡片边框、分割线 |
| `success` | `#2E8A57` | 完成状态 |
| `warning` | `#E67E22` | 待确认、提示 |
| `danger` | `#FF3B30` | 删除、失败、退出 |

### 5.4 操作闭合调查

**WHEN** 任何页面包含按钮、卡片、Tab、统计项、上传入口或列表操作 **THEN** 必须能找到真实 handler、目标路由或接口，并记录失败态、重复点击保护和返回路径。

“只显示文案”“只弹即将开放”“跳转后丢失 Tab 壳层”“点击模板却没有携带具体模板”均计为未闭合。

### 5.5 后续实施门禁

**WHEN** 3.0 开始实现 **THEN** 必须：

- 先完成主题 Token 与共享壳层，再批量迁移页面；不得在 22 个页面继续复制硬编码颜色。
- 保留 `pkg-actor-card` 分包边界，新增向导组件不得进入主包。
- 每轮 UI 改动均核对 `src`、`dist/build/mp-weixin`、`dist/dev/mp-weixin` 三侧，并遵循 00-219 的 scoped hash 清理与一致性流程。
- 继续执行 `vue-tsc`、`build:mp-weixin`、`verify:nav-title`、`verify:actor-card-attachment`、`audit:mp-package`。
- 涉及 API、数据库、已发布卡数据或公开观看页的改变，先做发版兼容评估并回填对应 Spec。

## 6. 当前调查结论摘要

- 5 张参考图覆盖的页面均已有 2.0 结构雏形，但 `step-photos`、`step-works`、`mine` 的操作与图稿仍不完全一致。
- 8 个用户可达页面仍明确使用旧棕米色主题：登录、演员档案编辑、实名认证、历史分享详情、资料库、资料导入复核、视频播放器、WebView。
- 共享组件和 `_tokens.scss` 仍保留旧主题；13 个蓝白页面大量硬编码颜色，形成 Token 与页面实现分裂。
- TabBar 选中图标位图仍为橙色，且 `rank.png` 同时被名片夹和素材库复用；素材库主包页只是 `redirectTo` 分包页，Tab 壳层不稳定。
- 3.0 需要同时处理视觉一致性、页面信息架构、真实可达性和操作闭环，不能按“逐页改背景色”交付。
