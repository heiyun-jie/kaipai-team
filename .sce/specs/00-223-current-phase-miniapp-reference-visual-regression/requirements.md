# 小程序参考图视觉标注、回归对比与风格模板

> 状态：Spec 已创建，待采集运行态截图。
> 上游：00-220（页面与缺口调查）、00-221（3.0 视觉/交互合同）、00-222（向导素材与排序真实能力）。
> 本轮授权：按五张本地视觉图建立逐页标注、截图对比和可复用风格模板；不以泛化的“蓝白风格”替代实际图稿结构。

## 1. 概述

本 Spec 将五张视觉参考图转换为可执行的视觉回归合同。它定义图稿版本、归一化坐标、页面锚点、组件模板、截图采集条件、差异判断与证据记录方式。

本 Spec 不直接更改前端、后端、数据库和构建产物；实现改动必须在完成对应页面的标注和截图差异登记后，另按任务实施。运行态截图未采集前，只能说明“源码待验证”，不得声明页面已对齐。

## 3. 用户故事

- 作为产品验收者，我希望每个图稿模块都有明确的视觉锚点和允许误差，而不是收到笼统的“已做成蓝白风格”。
- 作为开发者，我希望复用一份页面、卡片、进度、网格和底部操作的风格模板，而不是在五个页面分别猜测间距和圆角。
- 作为演员，我希望图中的上传、排序、继续编辑和服务入口仍指向真实能力，不因为视觉对齐被替换成无效入口。

## 4. 功能需求

### 4.1 页面级视觉标注

每张图必须登记：平台顶部区、导航、页面标题、进度、正文首个模块、连续卡片、固定底栏和 TabBar 的可见边界；每个锚点至少记录相对横向位置、相对纵向位置、宽高或间距、文字层级和负责的源码容器。

**验收标准**：

- WHEN 实施某一路由的视觉调整 THEN 先在 `reference-layout.md` 找到该路由的目标锚点和真实源码容器。
- WHEN 用户反馈位置或比例不对 THEN 只修改被标注的直接容器，不能同时猜改父级和相邻模块。
- WHEN 图稿含平台状态栏或微信胶囊 THEN 该区域只作对齐参考，不作为业务页面的像素差异项。

### 4.2 可复用风格模板

必须从五张图提取并维护以下模板：`ReferencePageShell`、`ReferenceNav`、`ReferenceProgress`、`ReferenceSection`、`ReferenceCard`、`ReferenceSegmentedTabs`、`ReferenceMediaGrid`、`ReferenceBottomCta` 和 `ReferenceTabBar`。

模板定义视觉职责和状态，不要求立即新增同名 Vue 组件；在确认重复度与分包影响前，页面可以先以局部样式实现。

**验收标准**：

- WHEN 页面使用品牌蓝 THEN 仅用于主 CTA、进度、链接、选中态和认证强调；普通卡片、正文和页面画布保持中性色层级。
- WHEN 页面属于五张参考图范围 THEN 主体横向留白为 40rpx、普通卡片为细边框白底、圆角为 16rpx、连续模块间距为 16rpx 或 32rpx 的节奏。
- WHEN 图稿与真实业务冲突 THEN 保留 00-221/00-222 的真实合同，记录为“视觉示例数据”，不得以放宽上限、增加假入口或改变 API 行为来伪造截图。

### 4.3 运行态截图对比

实际截图必须在已知设备宽度、登录状态和数据条件下采集，并与同一路由的参考图做覆盖式比对。比较对象是可控业务区：页面画布、导航、模块边界、卡片、文本层级、按钮、媒体网格和 TabBar；头像、真实图片、人名、统计数值等动态内容允许掩膜，不作为布局通过依据。

**验收标准**：

- WHEN 某页提交视觉验收 THEN 必须同时有参考图、实际截图、截图条件、产物 `data-v` 哈希和差异结论。
- WHEN 产物或运行态哈希与 `src` 不一致 THEN 先按 00-219 / 00-216 排查产物与缓存，禁止继续改源码猜样式。
- WHEN 主要锚点的归一化偏差超过 8rpx，或文字、卡片、CTA、媒体格出现重叠/截断 THEN 该页不得标记通过。

### 4.4 真实操作映射

视觉图中的每个可操作元素必须映射至已有 handler、路由或 API。静态图的示例数据不得改变真实限制：生活照片最多 12 张、帮助与设置无真实页面时不新增入口、首页模板仍按已选风格过滤、向导资源仍按 assetId 绑定和回读。

**验收标准**：

- WHEN 照片页初始加载 THEN 只显示“调整顺序”入口；用户显式进入排序模式后才显示上移/下移操作。
- WHEN 个人中心服务项没有真实目标页面 THEN 不得因图稿存在文字而增加无效入口。
- WHEN 首页渲染模板网格 THEN 保留当前风格 Tab 的真实过滤语义，不能用图稿四张示例图替换为同屏伪数据。

## 5. 非功能需求

- 截图对比按相同页面路由、相同设计宽度和明确数据条件执行；截图中必须可识别当前产物的 `data-v` 哈希或相等性报告。
- 不使用桌面鼠标、键盘、窗口激活、置顶、强制前台、抢占焦点、整屏控制或桌面级截图来获取证据。用户提供运行态截图，或在用户明确允许并确认不影响其使用时再执行可见窗口核验。
- 每次只调整一个页面的一组直接视觉锚点；完成截图证据前不进入下一组大范围视觉修改。
- 所有新增材料保持 Spec 可追溯性，并同步登记到 `.sce/specs/README.md`。

## 6. 约束与边界

1. 00-221 的颜色、字体、状态和真实操作合同优先于任何静态视觉示例。
2. 00-222 的素材库会话、assetId、排序、上传和保存回读合同不得被本 Spec 改写。
3. `dist/build`、`dist/dev` 和微信开发者工具运行态不是同一证据层；未完成三侧核验时不得宣称视觉已生效。
4. 本 Spec 的“风格模板”是设计/实现模板，不生成假的演示数据、不引入新后端接口、不影响当前用户的桌面使用。
