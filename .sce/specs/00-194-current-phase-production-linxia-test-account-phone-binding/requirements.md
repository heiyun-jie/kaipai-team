# 00-194 当前阶段生产林夏测试账号迁移与手机号绑定

## 1. 概述

旧线上库已有一个用于展示和推广的「林夏」测试演员账号。当前生产库只存在目标推广手机号自动注册出来的空壳账号，未包含林夏演员档案和分享资产。当前需要把旧线上「林夏」账号及其直接资产迁移到当前生产库，并让目标推广手机号登录后进入该林夏账号，后续用于小程序推广。

本轮是生产数据迁移 / 绑定任务，不是功能开发任务。目标是在不改业务代码、不重建分享卡的前提下，通过受控 SQL 从旧线上库迁移「林夏」演员账号、档案、分享卡、实名、邀请、能力和 AI 分享图相关直接资产到当前生产库，并留下可回滚的数据库快照和 SCE 执行记录。

为避免个人手机号进入仓库，Spec 与脚本记录只允许保存脱敏手机号；完整手机号只能通过执行时环境变量 `KP_BIND_TARGET_PHONE` 注入。

## 2. 用户故事

- 作为推广者，我希望使用自己的手机号登录小程序后，直接进入已有的「林夏」测试演员账号，继续使用其作品、分享页和名片资产。
- 作为维护者，我希望本次线上数据改动只影响旧线上库中一个明确的「林夏」演员账号，不误迁其它同名账号。
- 作为维护者，我希望当前生产库目标手机号如已被空壳账号占用，执行流程必须先确认空壳账号无资产，备份并软删除后再迁入林夏账号。
- 作为维护者，我希望数据变更前有备份、变更后有验证，必要时能按备份恢复。

## 3. 功能需求

### 3.1 旧线上源账号唯一定位

**描述**：执行前必须在旧线上源库中定位唯一的目标「林夏」演员账号。本轮已通过只读诊断确认目标源账号锚点为 `source_user_id=10007`，仍必须校验该账号满足：

- `user.deleted = 0`
- `user.user_type = 1`
- `user.phone` 等于目标推广手机号
- 关联的 `actor_profile.deleted = 0`
- `user.user_name / actor_profile.nick_name / actor_profile.real_name` 至少一个命中「林夏」

**验收标准**：

- WHEN 源库 `source_user_id=10007` 命中目标手机号、演员身份、有效档案和「林夏」名称条件 THEN 允许进入生产空壳账号门禁。
- WHEN 源库账号不存在、非演员、无有效档案或不命中「林夏」名称条件 THEN 阻断执行。
- WHEN 源库目标账号分享卡数量小于 `1` THEN 阻断执行，避免迁入空账号。

### 3.2 当前生产目标手机号空壳门禁

**描述**：当前生产库中目标推广手机号已由小程序登录自动注册为空壳演员账号。迁移前必须确认该账号没有档案、分享卡、实名、邀请码、能力或权益资产；否则不能软删除，必须另开合并 Spec。

**验收标准**：

- WHEN 当前生产库 `user.phone = KP_BIND_TARGET_PHONE` 的有效用户数量为 `1` 且资产计数为 `0` THEN 允许备份并软删除空壳账号。
- WHEN 当前生产库目标手机号有效用户数量不是 `1` THEN 阻断执行。
- WHEN 当前生产库目标手机号账号已有任一资产 THEN 阻断执行，不做迁移。

### 3.3 主账号迁入

**描述**：把旧线上源库 `source_user_id=10007` 的 `user` 行按原主键迁入当前生产库。迁入后当前生产库只有一个未删除用户持有目标推广手机号，登录链路按 `user.phone` 查询到林夏账号。

**验收标准**：

- WHEN 迁移完成 THEN 当前生产库 `user.user_id=10007` 存在且 `phone` 等于目标推广手机号。
- WHEN 迁移完成 THEN 当前生产库目标推广手机号未删除用户数量为 `1`。
- WHEN 迁移完成 THEN 原生产空壳账号已备份并软删除，且手机号改为归档值避免登录冲突。

### 3.4 演员档案联系电话对齐

**描述**：`actor_profile.phone` 是演员档案私有/授权联系方式的重要来源；绑定推广手机号后，林夏档案联系电话也要与目标推广手机号一致，避免登录账号与档案联系电话分裂。

**验收标准**：

- WHEN 更新完成 THEN `actor_profile.user_id = source_user_id` 的有效档案 `phone` 等于目标推广手机号。
- WHEN 有效演员档案数量不是 `1` THEN 阻断执行，避免误改多档案或无档案账号。

### 3.5 直接资产迁移

**描述**：本轮按原主键迁移旧线上林夏账号的直接资产，避免重写分享卡外键。迁移范围包括：

- `user_share_card`
- `actor_card_config`
- `actor_share_preference`
- `identity_verification`
- `identity_verification_owner`
- `invite_code`
- `referral_record`
- `capability_account`
- `capability_change_log`
- `user_entitlement_grant`
- `actor_ai_profile_card_task`
- `actor_ai_profile_card_page`
- `share_card_contact_request`
- `share_card_view_history`

**验收标准**：

- WHEN 迁移完成 THEN 当前生产库 `user_share_card` 数量等于源库林夏账号数量。
- WHEN 迁移完成 THEN 当前生产库分享配置、偏好、实名、邀请和能力资产通过同一 `user_id / actor_profile_id / share_card_id` 可读。
- WHEN 任一迁移表发生主键冲突或插入行数与源库计数不一致 THEN 事务回滚。

### 3.6 备份与回滚能力

**描述**：执行迁移前必须在生产库中创建本轮专用备份表，至少覆盖空壳账号、源账号主键可能涉及的目标库现有行，以及本轮迁移范围内的所有目标表。

**验收标准**：

- WHEN `migration-apply` 执行前 THEN 备份表已存在，并包含目标生产空壳账号更新前数据。
- WHEN 需要回滚 THEN 可用备份表恢复软删除前目标账号，并删除迁入的源账号资产。
- WHEN 执行记录落档 THEN 只记录备份表名、用户 ID、分享卡数量和脱敏手机号，不输出完整手机号。

## 4. 非功能需求

- 不在源码、Spec、发布记录或聊天总结中持久化完整手机号；完整手机号只允许作为执行时环境变量存在。
- 不新增后端接口，不修改小程序代码，不修改后台页面。
- 不使用 mock 数据作为生产数据变更依据。
- 不通过手工登录数据库直接执行未留档 SQL；必须使用本 Spec 的脚本或标准 backend helper 执行。
- 执行输出必须脱敏手机号，格式为 `前三位 + **** + 后四位`。

## 5. 约束条件

- 目标环境为生产数据库，默认 `--mysql-database kaipai_prod`、`--mysql-container kaipai-mysql`。
- 生产远端执行必须复用 `.sce/runbooks/backend-admin-release/scripts/kaipai-backend-release-helper.sh` 的 MySQL validation/apply 能力。
- 如果预检查无法唯一定位账号或目标手机号已被占用，必须停止；不得为了赶推广绕过门禁。
- 若本次实际需要把目标手机号已有账号与林夏账号合并，本 Spec 不覆盖，必须另建账号合并 Spec。
