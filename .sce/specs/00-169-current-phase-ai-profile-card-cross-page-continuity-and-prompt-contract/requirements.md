# AI 分享图跨页连续生图与中文 prompt 契约 Requirements

> 状态：已被 `00-171-current-phase-ai-profile-card-single-cover-theme-flow` 取代。跨页连续性不再是当前生成合同，因为新任务只生成一张封面背景图。

## 1. 概述

现有 `00-168` 已经把 AI 分享图收口为固定三页资料册，但三页之间目前仍主要是“同风格三页”，不是“同一本资料册里自然翻页的连续画面”。当前需要新增的能力不是改页数，而是把**第二页如何沿用第一页结尾**、**第三页如何沿用第二页结尾**，以及**prompt 用中文如何更稳定地表达**，沉淀成明确契约。

本需求要解决两件事：

1. 三页之间必须建立明确的视觉接续关系。
2. prompt 必须支持中文为主的可读表达，同时保留短、硬、稳定的英文约束尾，避免模型在长英文说明里跑偏。

本 spec 仍然是设计和契约文档，不直接修改业务代码。

## 2. 用户故事

### 2.1 产品与运营

作为需要审核 prompt 和最终效果的人，我希望后台里看到的是中文业务描述，而不是一长串难以维护的英文说明，这样我更容易确认构图、风格、背景和禁用项。

### 2.2 后端研发

作为实现生图链路的人，我希望第二页和第三页不是重新开一张“孤立海报”，而是明确继承上一页的尾部视觉特征，这样三页才像同一组连续资料页。

### 2.3 测试与验收

作为做真人 E2E 的人，我希望能明确截图验证每一页的接续点，而不是只看单页好不好看，这样更容易发现页与页之间的断层、黑缝和突兀跳变。

## 3. 功能需求

### 3.1 跨页连续性必须显式建模

**描述**：三页资料册必须支持“上一页结束 -> 下一页开始”的明确视觉续接，而不是依赖模型自行猜测。

**验收标准**：

1. WHEN `cover` 生成完成 THEN 系统必须从 `cover` 的尾部提取一个可复用的连续性参考带，作为 `resume` 的起始参考。
2. WHEN `resume` 生成完成 THEN 系统必须从 `resume` 的尾部提取一个可复用的连续性参考带，作为 `gallery` 的起始参考。
3. WHEN 生成 `resume` THEN 其 prompt 或 provider 参考输入必须显式包含 `cover` 的尾部连续性参考。
4. WHEN 生成 `gallery` THEN 其 prompt 或 provider 参考输入必须显式包含 `resume` 的尾部连续性参考。
5. WHEN 连续性参考存在 THEN 参考带必须来自上一页的明确裁切区域，而不是整张上一页原图。
6. WHEN 连续性参考缺失 THEN 系统必须进入降级态，并记录为“文字 continuity only”或同等可审计状态，而不是静默放弃接续。

### 3.2 跨页连续性只约束背景，不复制内容

**描述**：第二页、第三页需要继承的是色彩、光线、纹理、空间方向和氛围，不是复制第一页的人像、文字或前景组件。

**验收标准**：

1. WHEN `resume` 或 `gallery` 使用上一页参考带 THEN prompt 必须强调“延续上一页结尾的色彩、光线、材质和空间方向”，而不是复刻人物主体。
2. WHEN `resume` 或 `gallery` 生成结果中出现人物主体 THEN 系统必须判定为不符合连续背景契约，并允许重试当前页。
3. WHEN `resume` 或 `gallery` 生成结果中出现可读文字、二维码、Logo、标签或 UI 形状 THEN 系统必须判定为不符合契约，并允许重试当前页。
4. WHEN `cover` 生成完成 THEN 页面底部必须预留一段“过渡区”，为下一页接续做准备。

### 3.3 prompt 必须中文为主

**描述**：用于后台配置、调试和审阅的 prompt 应以中文为主表达业务意图，减少冗长英文说明带来的歧义和维护成本。

**验收标准**：

1. WHEN 生成 prompt THEN 构图、风格、背景、页面角色、接续说明必须优先使用中文表达。
2. WHEN 生成 prompt THEN 必须保留一段短、硬、稳定的英文约束尾，例如 `Plain, unmarked, symbol-free`。
3. WHEN 生成 prompt THEN 禁止把长篇英文说明作为主要业务描述。
4. WHEN prompt 中需要表达禁用项 THEN 可以用中文补充“不要可读文字、水印、Logo、标签、二维码、UI 形状”，但不得依赖 OCR 作为主要控制手段。

### 3.4 页面职责必须稳定

**描述**：三页依旧必须承担稳定职责，只是在视觉上形成连续接续。

**验收标准**：

1. WHEN 生成 `cover` THEN 允许保留演员主视觉和身份感，但仍要明确底部过渡区。
2. WHEN 生成 `resume` THEN 必须以资料背景和信息承载为主，不能再重复封面级人物主视觉。
3. WHEN 生成 `gallery` THEN 必须以照片墙、作品图与视频入口的背景承载为主，不能再重复封面级人物主视觉。
4. WHEN `resume` 与 `gallery` 接续上一页 THEN 只能继承背景气质，不得继承最终业务文字或前景卡片布局。

### 3.5 参考输入必须可追溯

**描述**：每一页用什么参考、引用了哪一页的尾部、采用了什么 prompt 语言策略，都必须可追踪。

**验收标准**：

1. WHEN 页面生成任务落库 THEN 必须保存页面 prompt、连续性参考来源、连续性参考带位置、provider、model、状态和失败原因。
2. WHEN QA 回看生成结果 THEN 必须能区分“参考带继承失败”与“prompt 语义失败”。
3. WHEN 页面重试 THEN 必须保留本次重试所依赖的上一页参考版本，避免出现无法复现的结果。

### 3.6 失败与重试策略

**描述**：连续性问题是当前页问题，不能因为第二页或第三页失败就把整条链路搞成不可定位状态。

**验收标准**：

1. WHEN `cover` 失败 THEN 整体任务必须失败，因为它是后续页面的起点。
2. WHEN `resume` 或 `gallery` 失败 THEN 系统必须只重试当前失败页，不得重新生成已经成功且无需变化的前序页。
3. WHEN 当前页重试后仍不符合连续性契约 THEN 系统必须保留失败原因，而不是用静默 fallback 掩盖问题。

## 4. 非功能需求

1. Tencent 混元的最终提交 prompt 必须保持简洁，避免超长 prompt 导致稳定性下降。
2. prompt 的中文可读性必须优先于英文营销式描述。
3. 连续性要求以“视觉自然衔接”为目标，不要求像素级拼接。
4. 连续性验证必须支持截图级审查，便于在 `cover / resume / gallery` 的接缝处发现断层。
5. 仍然不得依赖 OCR 作为连续性控制主路径。

## 5. 约束条件

1. 不得把页数开放成后台自由配置项。
2. 不得使用整张上一页作为下一页的默认 provider 输入。
3. 不得把真实业务文字交给图片模型绘制。
4. 不得把 OCR 作为 prompt 控制的主要来源。
5. 不得破坏现有固定三页顺序与旧单页 artifact 兼容性。

## 6. 非目标

1. 本需求不实现任意页数的长卷模式。
2. 本需求不实现用户手动调节页与页的接缝方式。
3. 本需求不把 OCR 升级成主要的内容控制方案。
4. 本需求不把三页合成一张超长图作为必做项。
5. 本需求不重做当前的页面业务信息结构，只处理跨页连续性和 prompt 契约。

## 7. 验收总则

1. `cover -> resume -> gallery` 的视觉接续关系必须可以在截图里确认。
2. prompt 必须以中文为主，且保留固定短英文约束尾。
3. 连续性参考必须是上一页尾部裁片，而不是整页复用。
4. 页面失败必须可定位到具体页和具体原因。
5. 旧 artifact、旧详情页和现有三页顺序仍必须可用。
