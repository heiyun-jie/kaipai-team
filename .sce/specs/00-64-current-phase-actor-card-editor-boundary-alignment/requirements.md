# 00-64 当前阶段分享卡编辑页边界对齐（Current Phase Actor Card Editor Boundary Alignment）

> 状态：规划中 | 优先级：最高 | 依赖：00-62 current-phase-minimal-share-card-mvp-alignment，00-63 current-phase-share-card-latest-state-alignment，05-05 card-share-membership，05-11 fortune-driven-share-personalization
> 记录目的：把 `pkg-card/actor-card/index` 当前残留的旧会员/命理/受众视角叙事、编辑能力缺口与公开页预览缺口收口为独立 Spec，防止页面继续同时承担旧分享产品和当前 MVP 的双重职责。

## 1. 背景

当前 `pkg-card/actor-card/index` 已被定位为“单卡编辑 / 预览页”，但页面仍然残留多块旧主线逻辑：

- 会员能力矩阵、会员 gating 与跳转会员页叙事仍然存在
- 命理驱动主题、幸运色入口仍然存在
- `剧组视角 / 品牌视角 / 朋友转发` 这类受众视角 selector 仍然存在
- 代表照片与高亮经历虽然已有后端字段，但前端仍缺少显式可编辑入口
- 页面缺少“预览公开名片”这个当前最小编辑闭环所必需的动作
- 配色保存、公开页生效与编辑门禁的边界仍不清晰

如果不把它单独升为 Spec，后续很容易一边删旧 UI、一边又保留旧 gating，最终继续形成半新半旧的编辑页。

## 2. 范围

### 2.1 本轮必须处理

- 收口 `pkg-card/actor-card/index` 的页面职责
- 清理不属于当前 MVP 的旧会员 / 命理 / 受众视角 UI 与文案
- 定义代表照片 / 高亮经历 / 配色的最小可编辑能力
- 定义“预览公开名片”按钮与跳转闭环
- 明确编辑页保存后，公开页与编辑预览页的生效规则

### 2.2 本轮不处理

- 一模板多卡实例重构
- 模板解锁资格模型重构
- 后端分享卡实例生成规则重构
- 会员、命理能力本身的业务实现扩展
- 全新视觉稿重做

## 3. 需求

### 3.1 页面边界收口

- **R1** `pkg-card/actor-card/index` 当前阶段必须只承担“单张分享卡编辑 / 单张分享卡预览 / 单张分享卡公开页预览入口”职责。
- **R2** 页面不得继续承担旧“会员能力中心”叙事；与会员等级、会员升级、会员海报能力绑定的旧 UI 必须移除。
- **R3** 页面不得继续承担旧“命理驱动主题”叙事；命理主题能力项、幸运色引导按钮、命理说明入口必须从当前编辑页移除。
- **R4** 页面不得继续保留 `剧组视角 / 品牌视角 / 朋友转发` 这类受众视角 selector；当前 MVP 公开分享口径必须统一。
- **R5** 页面所有保留控件都必须直接服务于“编辑当前卡片内容并预览公开结果”，不得保留只服务旧分享叙事的噪音模块。

### 3.2 最小编辑能力

- **R6** 编辑页必须允许用户显式选择当前卡片的代表照片，不得只展示默认推导结果。
- **R7** 编辑页必须允许用户显式选择当前卡片高亮拍摄经历，不得只展示默认场景推导结果。
- **R8** 编辑页必须允许用户编辑并保存当前卡片的：
  - 主配色
  - 强调色
  - 背景色
  - 布局样式
- **R9** 上述保存能力不得继续绑定旧会员 gating；若当前阶段允许编辑，则保存链必须直接可用；若不允许，必须在 Spec 中明确整体禁用，而不是页面局部残留半可用状态。
- **R10** 编辑页必须明确区分：
  - 通用演员资料由档案页维护
  - 当前卡片的展示配置由本页维护

### 3.3 公开预览闭环

- **R11** 编辑页必须新增明确的“预览公开名片”按钮。
- **R12** “预览公开名片”必须跳转到真实公开页 `pages/actor-profile/detail`，并携带当前 `shareCardId`，不得跳回旧分享编辑页或本地假预览。
- **R13** 用户在编辑页保存成功后，再次打开公开页时，必须看到最新代表照片 / 高亮经历 / 配色 / 布局结果。
- **R14** 编辑页内的视觉预览与公开页的最终结果，必须以同一套分享卡配置为事实源，不得一边读 preview overlay、一边读 personalization 最终态造成视觉分叉。

### 3.4 当前阶段明确移除项

- **R15** 以下模块必须从当前编辑页移除或下线：
  - 会员能力矩阵
  - 会员升级导流
  - 命理驱动主题能力项
  - 幸运色入口
  - 受众视角 selector
- **R16** 被移除模块如仍需未来保留，必须在 Spec 中标记为“后续能力批次”，不得继续挂在当前有效编辑链路上。

### 3.5 治理要求

- **R17** 本问题必须通过独立 Spec 固化，不得只停留在聊天中逐条修页面。
- **R18** 本 Spec 必须明确声明：当前不处理“一模板多卡实例”模型问题，该问题应由独立上位 Spec 处理。
