# 00-67 当前阶段分享主题语义对齐（Current Phase Share Theme Semantic Alignment）

> 状态：待执行 | 优先级：高 | 依赖：00-63 current-phase-share-card-latest-state-alignment，00-64 current-phase-actor-card-editor-boundary-alignment，00-66 current-phase-share-theme-request-fact-investigation
> 记录目的：基于 `00-66` 已确认的请求与代码事实，把“编辑页三色配置”和“公开页真实视觉区域”重新对齐，收口主题事实源，避免继续出现“已保存但公开页映射不符合预期”的反复返工。

## 1. 背景

`00-66` 已确认当前问题不是简单的“颜色没保存”，而是：

- `primaryColor` 当前主导 `surface / surfaceStrong`，视觉权重过大
- `accentColor` 当前只弱参与头部渐变
- `backgroundColor` 当前只弱参与页面底色起点
- `pages/actor-profile/detail` 没有直接信任后端 `theme`，而是在前端再次重算主题

这导致编辑页中的“主色 / 强调色 / 背景色”语义，与公开页真实视觉映射不一致。

## 2. 范围

### 2.1 本轮必须处理

- 固化三色字段的产品语义
- 固化公开页主题事实源
- 调整公开页主题消费与编辑页预览映射
- 保证编辑页保存后，公开页视觉变化可预测、可解释

### 2.2 本轮不处理

- 大幅重做编辑页 UI 结构
- 新增更多颜色字段
- 推进 fortune theme 新能力
- 多实例卡片模型改造

## 3. 需求

### 3.1 三色语义

- **R1** 必须明确 `primaryColor`、`accentColor`、`backgroundColor` 在公开页分别对应哪些固定视觉区域。
- **R2** 禁止继续使用“主色主导所有层次、其他颜色弱参与”的隐式语义，而不在产品与实现中显式说明。
- **R3** 编辑页色盘文案与公开页真实效果必须一致，用户调整后应能预期结果。

### 3.2 主题事实源

- **R4** 公开页主题必须收口为单一事实源，禁止后端聚合 `theme` 与前端本地重算主题长期双轨并存。
- **R5** 若保留后端 `theme` 为主题事实源，前端公开页必须直接消费该结果，不得再私自重算并改写语义。
- **R6** 若保留前端重算，则必须同步删除后端 `theme` 的事实源角色，并统一所有页面与分享产物的重算规则。

### 3.3 公开页消费

- **R7** `pages/actor-profile/detail` 必须明确区分：
  - 内容配置消费链：`highlightedPhotos / highlightedExperiences / tagOrder`
  - 视觉主题消费链：`primary / accent / background`
- **R8** 公开页必须把三色映射到稳定区域，不能再让 `accentColor` 只成为“几乎看不见的辅助色”。
- **R9** 公开页背景、hero、卡片、强调元素之间的颜色职责必须清晰，避免多层派生后失真。

### 3.4 编辑页预览

- **R10** 编辑页主题预览必须与公开页使用同一套颜色语义，不能只做近似模拟。
- **R11** 编辑页“预览公开名片”跳转前后，颜色呈现必须可对照验证。

### 3.5 验证

- **R12** 必须补一轮请求样本与页面截图证据，验证保存值、聚合值、公开页渲染值一致。
- **R13** 修复完成后，执行记录中必须明确“主色 / 强调色 / 背景色”各自落到哪些样式变量和页面区域。

## 4. 验收标准

- [ ] 已明确三色字段的产品语义与页面区域
- [ ] 已确定公开页主题的单一事实源
- [ ] 已调整公开页颜色消费，避免 `primaryColor` 独占大部分视觉层次
- [ ] 已对齐编辑页预览与公开页实际效果
- [ ] 已在执行记录中补齐请求样本、页面消费点与修复证据
