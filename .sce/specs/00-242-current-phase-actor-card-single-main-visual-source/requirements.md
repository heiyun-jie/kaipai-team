# 演员卡单一首图来源收口

> 状态：源码 / build / 后端已完成；步骤页扩图可见性由 `00-245` 接管，`dist/dev` 同步与运行态核验待安全窗口（2026-08-28）。
>
> 产品裁决：演员卡“背景图”和“首图”在业务逻辑上是同一张图。`00-241` 的字段区分仅作为历史事实保留，本 Spec 覆盖其产品语义。

## 1. 问题

`pkg-actor-card/step-visual/index` 当前把系统背景图库与用户主视觉照片拆成两个必选概念，首页模板预选也只写 `backgroundImageUrl`。生成门禁却只认可 `source_image` / `sourceImageUrl`，公开详情 Hero 又优先使用 `backgroundImageUrl`，导致同一张演员卡可能在向导、生成页和分享详情显示不同图片。

## 2. 功能需求

### 2.1 单一首图

- 页面只展示一个“首图”概念。
- 模板图库、素材库和手机上传只是首图的三种来源，任一时刻只能有一个有效选择。
- 选择模板图片后，该图片直接成为首图并可作为内部 AI 扩图输入；不再要求额外选择人物原图。
- 选择素材库或手机图片后，该图片直接替换模板图库首图。
- AI 扩图的后端字段和历史结果继续参与有效首图兼容解析；步骤页不展示或触发扩图，用户可见边界由 `00-245` 定义。

### 2.2 全链路同源

- 创建 Hub 接收首页模板预选时，必须把模板图片写成可完成步骤 1 的首图。
- 步骤完成状态、生成门禁、生成输入、名片列表封面、生成页和公开分享详情必须遵循同一有效首图优先级。
- 公开 DTO 的 `backgroundImageUrl` / `previewImageUrl` 为兼容旧前端继续保留，但同一次响应必须指向同一有效首图。

### 2.3 历史兼容

- 不删除或重命名 `background_image_url`、`source_image_url`、`expanded_image_url`，不新增数据库迁移。
- 有素材绑定时优先使用绑定；存在显式空绑定时不恢复已被用户替换的旧 `sourceImageUrl`。
- 仅有历史 `backgroundImageUrl` 或仅有历史 `sourceImageUrl` 的卡仍可完成、生成和公开展示。
- 旧客户端原请求字段继续可用；空字符串仅在步骤 1 请求中作为清理旧首图镜像的显式意图。

## 3. 非功能与发布兼容

- 后端变更为加法兼容，不改变 API 路由和响应字段，不需要数据库迁移。
- 新前端与新后端应同批进入测试环境；旧前端调用新后端仍保持原合同。
- 正式环境在 `00-236` 重新冻结候选前不得切流，本次变更会使现有候选摘要失效。
- UI 与运行核验遵守桌面非干扰规则，固定核对 `dist/dev/mp-weixin`。

## 4. 验收标准

- 页面不再出现“版式背景 / 主视觉原图”两套可见入口，只存在“首图”。
- 点击模板图库图片后无需再上传图片即可进入下一步并满足生成门禁。
- 模板图库、素材库、手机上传互相替换，内部扩图如被编排触发则使用当前首图。
- 分享详情 Hero 不被历史背景字段覆盖，公开 DTO 两个兼容图片字段同值。
- 前后端定向测试、前端专项门禁、构建、`src/build/dev` 等价和包体审计通过。
