# 00-238 发布后观察与旧运行时退场

> 状态：Spec 完成，实施未开始
>
> 上游：`00-237`；维护：`00-230` 双环境长期治理

## 1. 概述

本 Spec 定义正式切流和小程序发布后的观察窗口、指标、异常响应、应用回切、版本回退和旧后端退场条件。它确保“发布成功”不是只看首页 200，而是验证已有数据继续可用、测试环境继续隔离、线上错误没有积累。

## 2. 用户故事

作为发布负责人，我希望知道何时可以安全停止旧后端，以及什么信号出现时必须回切。

作为维护人员，我希望回退旧应用不会覆盖切流后新产生的数据。

## 3. 功能需求

### 3.1 建立观察窗口

**验收标准**：

- WHEN `00-237` 切流成功 THEN 启动至少 1-2 小时的高频观察窗口。
- WHEN 观察期间 THEN 采集 API 5xx、P95、登录失败、DB 连接池、Nacos、Redis、COS、短信/AI provider 错误和关键业务写入。
- WHEN 指标采集 THEN 记录为聚合值，不写 Token、PII 或完整 URL。

### 3.2 发布后业务回归

**验收标准**：

- WHEN 使用历史账号 THEN 资料、经历、intro、素材、旧分享和实名状态仍可用。
- WHEN 使用新账号 THEN 新素材、演员卡、生成、发布、分享和复制流程仍可用。
- WHEN 后台和正式小程序同时访问 THEN 没有缺表、缺列、合同字段或鉴权回归。

### 3.3 定义自动回切条件

**验收标准**：

- WHEN 连续出现核心 API 5xx、登录大面积失败、数据写入错误、越权或生产污染 THEN 立即回切旧 upstream。
- WHEN 新后端无法稳定连接数据库/Redis/Nacos THEN 回切，不通过删表解决。
- WHEN 小程序新版本异常但旧版本正常 THEN 触发微信版本回退/暂停新版本，后端保留双版本兼容。

### 3.4 保证回切数据安全

**验收标准**：

- WHEN 回切旧后端 THEN 保留新增表、字段、asset 和关系。
- WHEN 回切完成 THEN 新旧后端都不能覆盖或清空切流后新写入。
- WHEN 发现局部数据问题 THEN 使用定点修复和审计，不直接恢复发布前全库备份。

### 3.5 旧运行时退场

**验收标准**：

- WHEN 观察窗口稳定且业务回归通过 THEN 才允许停止旧后端容器。
- WHEN 停止旧容器前 THEN 保留旧 JAR、镜像、compose、Nginx 回切配置和数据库备份。
- WHEN 旧容器退场 THEN 测试容器、测试 schema、测试 Nacos 和测试域名继续可用。
- WHEN 退场完成 THEN 记录正式状态和下一批测试入口。

### 3.6 关闭发布批次

**验收标准**：

- WHEN 观察完成 THEN 生成 `STABLE`、`ROLLED_BACK` 或 `EXTENDED_OBSERVATION` 结论。
- WHEN 未完成数据/错误/回切调查 THEN 批次不得标记完成。
- WHEN 批次关闭 THEN 更新 `00-230` execution plan、风险登记和发布记录。

## 4. 非功能需求

- 观察过程不强制停止用户电脑或微信开发者工具，遵守桌面非干扰规则。
- 旧运行时的保留周期由发布负责人确认，至少覆盖观察窗口和微信版本回退可行期。
- 测试环境长期运行需有容量、费用和数据清理策略，不能无限增长。

## 5. 约束条件

- 退场是可逆运维动作，删除旧镜像/备份必须另行授权。
- 不因为“首页访问正常”跳过历史账号和写入回归。
