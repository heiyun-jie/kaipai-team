# 00-231 发布候选冻结与运维安全前置

> 状态：实施中，T1/T2 已完成，T3/T4 待执行
>
> 上游：`00-230`；下游：`00-232`、`00-233`、`00-234`

## 1. 概述

本 Spec 建立双环境发布的第一个不可跳过门禁：冻结唯一、可复现的发布候选，生成代码、产物和数据库迁移清单，并在任何远端诊断或变更前确认 release helper 已使用当前仓库的脱敏实现。

## 2. 用户故事

作为发布负责人，我希望测试通过的候选与最终生产发布完全相同，避免测试后继续混入未验证改动。

作为运维人员，我希望所有诊断记录默认脱敏，且已暴露凭据得到明确轮换结论。

## 3. 功能需求

### 3.1 冻结候选身份

**验收标准**：

- WHEN 创建候选 THEN 记录根仓库、后端、管理端和小程序的 commit SHA、分支和工作树状态。
- WHEN 使用 overlay 构建 THEN manifest 明确列出每个 overlay 相对路径和 SHA256，未列文件不得进入构建。
- WHEN 任一候选文件变化 THEN 原候选自动失效，必须生成新候选号。
- WHEN `V20260818_001__actor_card_media_binding.sql` 未被 Git 跟踪 THEN 候选不得冻结。

### 3.2 冻结迁移与产物清单

**验收标准**：

- WHEN 候选冻结 THEN 14 个迁移文件按 `00-230` 顺序记录文件名、大小和 SHA256。
- WHEN 构建完成 THEN 记录后端 JAR、管理端产物清单、小程序 test/release 产物的 SHA256。
- WHEN test/release 小程序构建完成 THEN 分别证明 API Base URL，不能只靠文件名区分环境。
- WHEN 生产依赖审计存在高危项 THEN 必须区分最终运行时可达依赖与仅在受控构建期执行的工具链；未知告警、critical、旧版运行时依赖或工具链代码进入发布产物时不得通过。
- WHEN 构建工具链风险被有条件接受 THEN 记录约束和明确到期时间，依赖输入变化或到期后必须重新评估。

### 3.3 建立运维脱敏门禁

**验收标准**：

- WHEN 运行 helper 安全测试 THEN 全部测试通过，未知环境变量和非结构化内容均被脱敏。
- WHEN 远端 helper 版本落后 THEN 在任何 runtime diagnostics 前先同步当前安全版本。
- WHEN 发布记录生成 THEN 不包含数据库密码、Token、手机号、身份证号、完整对象 URL 或云密钥。

### 3.4 处理凭据暴露风险

**验收标准**：

- WHEN 已确认旧 helper 曾输出敏感环境变量 THEN 建立凭据清单和轮换决定，不在 Spec 中记录凭据值。
- WHEN 高风险凭据尚未轮换或明确接受风险 THEN 不允许进入正式切流。
- WHEN 凭据轮换会影响现网 THEN 使用独立变更记录并先完成测试环境验证。

### 3.5 输出 GO / NO-GO 证据

**验收标准**：

- WHEN 所有门禁通过 THEN 输出不可变候选 manifest 和 `GO` 结论。
- WHEN 工作树不明确、产物不可复现、helper 未脱敏或凭据风险未处置 THEN 输出 `NO-GO`。
- WHEN 下游 Spec 启动 THEN 必须引用本 Spec 的候选号和 manifest SHA256。

## 4. 非功能需求

- Manifest 不保存秘密，只保存非敏感标识、相对路径、大小和哈希。
- 候选冻结不等于授权远端部署；远端 helper 同步和凭据轮换需单独明确授权。
- 所有时间使用带时区的 ISO 8601 或项目发布批次时间格式。

## 5. 约束条件

- 不清理用户工作树，不回退未归属改动。
- 不允许用“当前目录看起来正确”替代 commit/overlay 清单。
- 不允许测试通过后修改迁移 SQL 并沿用原候选号。
