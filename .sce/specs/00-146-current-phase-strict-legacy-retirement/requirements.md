# 00-146 Requirements

## 背景

- 用户已明确拒绝“兼容层 / 兜底 / 双轨治理仍保留也算完成”的审查标准。
- 本轮以“先备份，再物理删除，再重新审查”为唯一执行口径。
- 删除对象必须限定在已确认不再承载主链功能、仅继续暴露 legacy 治理语义的接口、前端入口、权限登记与 DTO。

## 目标

1. 删除分享卡 `legacy-summary / repair-legacy` 正式 API。
2. 删除后台管理端对应 API、类型、权限登记、页面入口与按钮。
3. 将后台可见层中的明显 `兼容 / fallback / 迁移期` 表述改为中性治理表述，避免继续把过渡态产品化。
4. 形成严格标准下的新一轮复审记录，不再复用此前宽松评分。

## 非目标

- 本轮不直接删除仍被运行时主链使用的默认普通卡补偿链。
- 本轮不直接删除仍被运行时代码读写的 `scene_key / actor_card_config_id` 等数据库字段。
- 本轮不直接接入 Flyway/Liquibase。

## 验收

- 删除项在代码仓内被物理移除，不再有 consumer。
- `kaipaile-server` 编译通过。
- `kaipai-admin` 类型检查与构建通过。
- 严格复审说明必须区分：
  - 已完成物理删除项
  - 仍阻塞严格 95 分的残留项
  - 为什么这些残留项当前不能强删
