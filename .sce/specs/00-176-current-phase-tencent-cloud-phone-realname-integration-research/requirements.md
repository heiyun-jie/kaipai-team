# 00-176 当前阶段腾讯云手机号与实名认证服务接入调研

## 1. 概述

当前项目已有两条相关主线：

- 登录域：`00-51` 已把正式短信能力降级为后续批次；`00-173` 已启用微信手机号一键登录；`00-174` 在验证码审核前隐藏短信登录入口。
- 实名域：`05-09` 已落地实名认证提交、后台人工审核和状态展示；第三方实名核验仍处于后续扩展范围。

本 Spec 只负责调研并生成腾讯云手机号服务与实名认证服务的接入文档，形成后续实现前的事实基线、候选方案、配置清单和验收门禁。不在本轮改代码、不接入真实密钥、不发布。

## 2. 用户故事

作为产品负责人，我希望明确腾讯云手机号相关服务与当前登录能力的关系，避免把短信验证码、微信手机号授权、运营商号码认证混为一谈。

作为平台维护者，我希望明确腾讯云实名认证服务的接入方式，判断当前人工审核链路应升级为身份证二要素、手机号三要素，还是人脸核身。

作为后端开发者，我希望在实现前拿到接口、配置、数据安全和验证门禁清单，避免后续边做边查导致密钥、个人信息或状态机处理出错。

## 3. 功能需求

### 3.1 现有 Spec 与代码事实盘点

**描述**：文档必须先梳理当前项目中登录、短信、微信手机号、实名认证相关的已存在 Spec 和运行时代码。

**验收标准**：

- WHEN 阅读调研文档 THEN 能看到 `00-51 / 00-173 / 00-174 / 05-09` 的边界说明。
- WHEN 阅读调研文档 THEN 能看到当前 `sendCode` 仍为开发态直返验证码。
- WHEN 阅读调研文档 THEN 能看到当前实名认证已具备提交、状态、后台审核、哈希去重，但第三方核验未接入。

### 3.2 腾讯云手机号服务候选方案

**描述**：文档必须区分腾讯云 SMS、腾讯云号码认证、腾讯云实名核身手机号要素核验三类能力，并给出当前项目推荐路径。

**验收标准**：

- WHEN 阅读调研文档 THEN 能知道短信验证码应优先看腾讯云短信 SMS。
- WHEN 阅读调研文档 THEN 能知道微信小程序手机号一键登录当前已由微信 `getPhoneNumber` 承接，不应重复接腾讯云 App 号码认证作为登录入口。
- WHEN 阅读调研文档 THEN 能知道手机号三要素核验属于实名域增强能力，不是短信发送能力。

### 3.3 腾讯云实名认证服务候选方案

**描述**：文档必须列出身份证二要素、手机号三要素、人脸核身三种接入深度，并说明与当前 `05-09` 状态机的结合方式。

**验收标准**：

- WHEN 阅读调研文档 THEN 能比较二要素、三要素、人脸核身的适用场景、接入复杂度和风险。
- WHEN 阅读调研文档 THEN 能看到推荐的分阶段路线。
- WHEN 阅读调研文档 THEN 能看到失败、异常、人工审核兜底的状态机建议。

### 3.4 配置、安全与合规清单

**描述**：文档必须列出腾讯云密钥、SMS 签名模板、实名核身资质、Nacos / 环境变量、个人信息保护和日志脱敏要求。

**验收标准**：

- WHEN 后续进入实现 Spec THEN 可以直接复用本轮配置清单。
- WHEN 后续进入发布前检查 THEN 可以直接复用本轮运行时门禁。
- WHEN 文档涉及身份证、手机号、姓名 THEN 明确禁止明文日志、前端密钥、仓库提交真实 secret。

### 3.5 后续实施拆分

**描述**：文档必须把后续实现拆成独立 Spec 建议，不把短信、实名、后台审核、运行配置混成一个大改动。

**验收标准**：

- WHEN 后续排期 THEN 能按短信正式通道、实名服务商接入、后台审核升级、发布配置门禁分别建 Spec。
- WHEN 任一服务未开通或资质未通过 THEN 不阻塞其他已完成主线。

## 4. 非功能需求

- 本轮不得提交腾讯云 `SecretId / SecretKey` 或任何真实短信签名、模板密钥。
- 本轮不得改动前端、后端和数据库运行代码。
- 本轮调研只引用腾讯云官方文档或项目内现有 Spec / 代码。
- 文档必须明确“事实”和“建议”的区别。

## 5. 约束条件

- 项目继续遵守“AI 大模型统一由后端封装，前端不直接调用”的同类安全边界：腾讯云短信和实名核验也必须由后端封装，前端不直连腾讯云 API。
- 身份证号后端加密存储、前端只展示脱敏值仍是硬约束；若当前实现与该约束不一致，必须在后续实现前修正。
- 手机号验证码入口当前仍受 `00-174` 审核态门禁约束，正式短信接入不等于立即恢复登录页短信表单。
