# 00-62 设计说明

## 1. 设计原则

- 以用户明确给出的 MVP 边界为准，不再由模型自行推断主线
- 先重排信息架构和事实源，再做页面级实现
- `用户档案`、`分享卡片`、`查看历史`、`联系方式授权` 四条线必须显式拆开
- 风格解锁、展示状态、联系方式权限必须收口到单一后端 / 后台输出
- 当前阶段不再把“公开演员列表”当成前端主入口

## 2. 信息架构重排

### 2.1 Tab 结构

| Tab | 页面目标 | 当前阶段核心模块 | 明确移除 |
|-----|----------|------------------|----------|
| `可以分享的卡片` | 作为用户自己的分享卡片主入口 | 风格模板区、我的可分享卡片列表、锁定样式提示、空态引导 | 演员公开列表、角色列表、通告列表 |
| `查看历史` | 回看自己实际浏览过的分享卡片 | 历史卡片列表、查看时间、授权状态、二次进入入口 | 广场浏览、搜索推荐 |
| `个人中心` | 收口个人资料与关系管理 | 档案信息、实名认证、已联系列表、我的名片入口 | 投递反馈记录、旧能力中心噪音模块 |

### 2.2 页面落点建议

| 逻辑页 | 建议路由落点 | 说明 |
|--------|--------------|------|
| 可分享卡片首页 | `pages/home/index` | 复用现 Tab 页位置，但内容改为卡片模板 / 卡片列表 |
| 查看历史 Tab | `pages/history/index` | 新增主包 Tab 页 |
| 个人中心 Tab | `pages/mine/index` | 继续作为个人中心，但模块按 00-62 重排 |
| 我的名片列表 | `pkg-card/card-list/index` 或现有卡片分包页重构承接 | 列出用户拥有的风格卡片 |
| 卡片编辑页 | `pkg-card/actor-card/index` 重构承接 | 从“总分享页”收口为单卡编辑 / 预览页 |
| 通用档案编辑页 | `pages/actor-profile/edit` | 只编辑基础档案 |
| 公开卡片详情页 | `pages/actor-profile/detail` | 只承担单张被分享卡片的公开查看与联系方式申请 |

## 3. 数据模型拆分

### 3.1 基础实体

| 实体 | 作用 | 关键字段 |
|------|------|----------|
| `ActorProfile` | 用户通用档案 | `userId`、基础资料、实名认证状态、联系方式原始数据 |
| `ShareCardTemplate` | 平台提供的风格模板 | `templateKey`、`styleName`、默认视觉、是否启用、解锁策略 |
| `UserShareCard` | 用户持有的具体卡片 | `cardId`、`userId`、`templateKey`、展示配置、状态 |
| `StyleUnlockPolicy` | 风格解锁策略 | `templateKey`、`requiredInviteCount`、启用状态 |
| `CardViewHistory` | 查看历史 | `viewerUserId`、`cardId`、`viewedAt` |
| `ContactRequest` | 联系方式申请 | `requestId`、`cardId`、`ownerUserId`、`viewerUserId`、`status` |

### 3.2 模型职责

- `ActorProfile` 只存通用资料，不存“都市卡标题”“古代卡文案”这类风格化字段
- `UserShareCard` 负责承接每张卡的风格展示差异、排序、启停和分享状态
- `StyleUnlockPolicy` 负责风格资格，不允许页面再自己写 `inviteCount >= n`
- `ContactRequest` 负责授权状态，不允许把“是否可看电话”只塞进页面局部状态

## 4. 首页与我的名片设计

### 4.1 首页结构

```text
可分享的卡片
  -> 风格模板带
     -> 普通（默认可用）
     -> 都市（锁定/已解锁）
     -> 古代（锁定/已解锁）
  -> 我的可分享卡片列表
     -> 已创建卡片
     -> 新增分享卡片 CTA
  -> 异常空态
     -> “先创建一张分享卡片吧”
```

### 4.2 默认卡与空态策略

- 正常注册链路：自动创建 `普通` 默认卡
- 历史补偿链路：登录后若查询到 0 张用户卡片，后端先尝试补默认卡
- 补偿前仍为空：前端只展示空态和新增入口，不回退旧首页列表

### 4.3 风格锁定展示

- `普通` 默认可用
- `都市`、`古代` 默认展示为可见但可锁定
- 锁定卡片要明确显示：
  - 还差多少邀请人数
  - 解锁后能做什么
  - 当前是否允许预览但不可创建

## 5. 查看历史设计

### 5.1 记录范围

- 只记录用户实际打开过的分享卡片或公开名片
- 不记录搜索页曝光、模板浏览或本人编辑页访问

### 5.2 列表结构

- 卡片封面 / 风格名
- 持卡人基础摘要
- 最近查看时间
- 联系方式授权状态
- 再次查看入口

## 6. 公开名片与联系方式设计

### 6.1 公开名片页职责

- 只消费某一张 `UserShareCard` 的公开展示结果
- 复用公共顶部组件，不再以旧演员详情页拼装思路扩散
- 底部固定主操作收口为：
  - 未申请：`申请联系方式`
  - 审批中：`等待对方处理`
  - 已同意：`查看联系电话`
  - 已拒绝：`重新申请` 或 `已拒绝`

### 6.2 联系方式申请流

```text
查看方打开分享卡片
  -> 点击申请联系方式
  -> 生成 ContactRequest(status=pending)
  -> 持卡人在自己的处理入口中同意/拒绝
  -> 若同意，查看方再次进入后可见电话
```

### 6.3 持卡人处理入口

- 当前阶段可先收口在“我的名片”列表详情或卡片编辑页内
- 处理入口至少要能看到：
  - 谁申请了
  - 申请的是哪张卡
  - 当前状态
  - 同意 / 拒绝操作

## 7. 个人中心设计

### 7.1 保留模块

- 档案信息
- 实名认证
- 已联系的列表
- 我的名片

### 7.2 隐藏与待评估模块

- `投递反馈记录` 当前阶段隐藏
- `名片能力中心` 当前不直接保留为旧入口；若继续保留，需要改造成围绕模板、解锁、分享和授权的说明层，而不是旧分享主线残留页

### 7.3 我的名片入口

- 进入后是卡片列表，不是单卡跳转
- 列表底部主操作是 `新增分享卡片`
- 卡片点击后进入对应风格卡的编辑页

## 8. 后端与后台设计

### 8.1 后端最小输出

- `我的卡片列表`
- `模板 / 风格列表`
- `风格解锁结果`
- `默认普通卡补偿结果`
- `查看历史列表`
- `联系方式申请列表 / 详情 / 审批结果`

### 8.2 后台最小治理

- 风格模板启停
- 每种风格邀请阈值配置
- 默认普通卡初始化策略
- 联系方式申请与审批记录回看

### 8.3 单一来源约束

- 风格是否已解锁
- 解锁需要多少邀请
- 联系方式是否可查看
- 当前卡片展示状态

以上四类判断都必须由后端统一返回，前端只负责呈现。

## 9. 对现有主线的影响

| 现有口径 | 00-62 新口径 |
|----------|--------------|
| 首页可继续作为演员 / 角色公开浏览入口 | 首页改为“可分享卡片 / 风格模板” |
| `actor profile` 可直接承担分享页主要配置 | `actor profile` 与 `share card` 分离 |
| invite 主要围绕邀请码 / 海报 / 分享操作页展开 | invite 退回邀请与资格支撑线，风格解锁由后台可配策略决定 |
| 公开详情页更像演员详情页 | 公开详情页改为单张分享卡片详情页 |
| 联系电话可按页面局部逻辑直接暴露 | 联系方式必须走申请 / 同意闭环 |
