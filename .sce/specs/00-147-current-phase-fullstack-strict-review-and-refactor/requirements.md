# 00-147 当前阶段全栈严格审查与重构推进

> 状态：进行中 | 优先级：最高
> 记录目的：把“重新审查整个项目，并按 API/数据库、小程序、后台的逐页 UI 与逐页 API 请求全面推进，低于 95 分必须继续修改”固化成一条总 spec 主线。

## 1. 审查目标

本轮必须重新审查整个项目，覆盖以下顺序与范围：

1. `API / 数据库`
2. `API / 小程序`
3. `API / 后台`
4. `小程序每个页面 UI`
5. `小程序每个页面 API 请求`
6. `后台每个页面 UI`
7. `后台每个页面 API 请求`

## 2. 评分规则

- 机器审查总分：`95`
- 用户人工审查分：`5`
- 项目总分：`100`

硬约束：

1. 机器审查分低于 `95`，禁止标记完成。
2. 禁止以“兼容旧代码 / 兜底路径 / 过渡态保留”作为完成依据。
3. 项目必须保持干净整洁，不允许保留已确认无必要的旧代码、旧接口、旧字段、旧文案、旧路由、旧页面壳。
4. 页面可复用的 UI 必须封装为组件复用，不能长期散落重复实现。
5. 任一审查结论必须有明确证据，包括文件路径、构建结果、接口路径、运行态产物或截图。
6. 禁止在未完成状态下，错误地切到收尾响应；未达到机器审查 `95 / 95` 前，只能继续推进、汇报进展和记录阻塞，不能输出完成态结论。

## 3. 审查拆分

### 3.1 后端与数据库线

- 审查 controller / service / entity / mapper / DTO / migration / schema 对齐情况。
- 审查数据库表、字段、约束、过渡字段、旧定位键是否已真正收口。
- 审查 API 是否仍暴露 fallback、repair、legacy、dual-path。

### 3.2 小程序线

- 审查 `pages`、`pkg-card`、`pkg-tools` 各页面 UI。
- 审查每个页面真实 API 请求、mock、兜底、旧链路、页面内重复 UI。
- 审查 `src`、`dist/build/mp-weixin`、`dist/dev/mp-weixin` 三层是否一致。

### 3.3 后台线

- 审查正式页面与 tooling 页面 UI。
- 审查每个页面 API 请求、权限、route meta、菜单、信息架构是否一致。
- 审查组件复用情况，重点覆盖壳层、筛选、表格、状态块、详情抽屉、按钮与权限控件。

- [ ] 已完成第一轮全量评分
- [ ] 任一低于 `95` 分的项已继续修改
- [ ] 已重新执行相关编译/构建/产物核验
- [ ] 已在主 spec 中记录所有扣分项、修改项、复评分与剩余阻塞
