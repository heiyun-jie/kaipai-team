# 演员卡步骤页内部 AI 自动扩图边界收口

> 状态：已完成（2026-09-01）。
>
> 上游：`00-222`、`00-241`、`00-242`、`00-243`、`00-244`；下游：`00-236` 人工验收。

## 1. 概述

步骤 1 曾把 AI 扩图作为演员可见操作展示，包含提交、处理中、结果对比、重试和 Provider 错误。这与产品裁决“扩图是内部操作，演员只需选择或上传一张首图，后端自动完成扩图”不一致。本 Spec 同时收窄演员可见边界并补齐后端自动编排、稳定来源绑定和失败可观测合同。

## 2. 用户故事

作为演员，我只需要选择或上传一张首图即可继续创建演员卡，不需要理解或操作内部 AI 扩图。

作为内部生成流程维护者，我希望首图选择或上传成功后由后端自动、异步、幂等地提交扩图任务，失败不阻断演员继续填写演员卡。

作为测试人员，我希望步骤页只出现首图选择相关状态，`src`、冻结候选、`dist/build`、`dist/dev` 和运行缓存来自同一产物。

## 3. 功能需求

### 3.1 步骤页只负责首图选择

- WHEN 打开演员卡创建步骤 1 THEN 页面只展示当前首图预览、模板图库、素材库选择和手机上传入口。
- WHEN 选择模板、素材或手机图片 THEN 三种来源继续替换同一个首图状态，下一步保存合同保持兼容。
- WHEN 首图为空、读取中、上传中或读取失败 THEN 页面只显示首图相关状态和对应恢复动作。

### 3.2 扩图不向演员暴露

- WHEN 打开、刷新或返回步骤 1，或查看创建中心/首页创建入口 THEN 演员可见文案不得展示“AI 扩图”或“智能扩图”标题、扩图按钮、处理中状态、结果对比、重新生成、失败重试或 provider 错误。
- WHEN 页面发生首图选择或上传 THEN 页面不得直接提交扩图任务或轮询扩图状态；首图保存或素材绑定成功后由后端自动提交扩图任务。
- WHEN 既有草稿含 `expandedImageUrl` THEN 步骤页不展示该结果；保存时继续遵守现有历史字段语义，来源变化时显式清理过期扩图结果。

### 3.3 后端自动扩图编排

- WHEN 步骤 1 URL 保存成功或 `source_image` 素材绑定完成 THEN 后端根据当前唯一首图自动提交异步扩图任务；接口响应不得等待 AI Provider 完成。
- WHEN 同一卡片、同一来源被重复保存或绑定 THEN 复用同一来源指纹对应的任务，不重复消耗 Provider；失败任务可由后续同来源保存受控重试。
- WHEN 来源是私有素材 THEN 任务只持久化稳定 `source_asset_id` 和来源指纹，调用 Provider 前即时签发访问 URL，不持久化短时签名 URL。
- WHEN 来源是模板或历史 URL THEN 任务持久化规范化 URL 和来源指纹。
- WHEN 扩图失败 THEN 演员保存/绑定仍成功，失败原因写入内部任务状态并记录服务端日志；演员页面不得展示 Provider 错误、重试按钮或失败状态。

### 3.4 来源一致性与历史兼容

- WHEN 首图来源变化 THEN 立即清理旧 `expanded_image_url` 及其来源指纹；旧异步任务完成后不得覆盖新来源。
- WHEN 生成、预览或公开页消费扩图结果 THEN 仅使用与当前唯一首图来源指纹一致的结果；历史无指纹数据保持读取兼容。
- 后端 `/api/actor-card/draft/{cardId}/expand-image` 及状态接口、前端 API 类型、`expanded_image_url` 字段和历史 DTO 保留，不删除或改名。
- `actor_ai_profile_card_task.source_image_url` 调整为可空，并新增稳定的演员卡、素材和来源指纹字段；迁移必须幂等并有真实 MySQL 合同测试。

### 3.5 产物与回滚

- 修改后必须重新构建小程序，并核对 `src`、`dist/build/mp-weixin`、`dist/dev/mp-weixin` 三侧步骤页内容；build/dev 的 WXML、WXSS、JS 及 scoped `data-v` 必须一致。
- 新 Candidate 的冻结 `mini-program-test` 是唯一事实源；同一冻结目录必须完整物化到 build/dev，准入门禁必须返回 `READY_FOR_MANUAL_ACCEPTANCE / exit 0`。
- 基线原文件 SHA256 必须保留；回滚脚本只在另一个本地副本验证恢复原始服务文件，不触碰测试或生产运行环境。
