# 演员卡素材库与创建向导接通

> 状态：T0-T5 已完成；当前下一项为 T6 构建、运行态与发布准备。
>
> 触发裁决：2026-08-18，用户要求“创建 specs 进行素材库的接通，另外需要跟创建流程打通”。本 Spec 承接 00-221 T0-3 中已经明确的“素材库选择与排序”交付项；帮助与反馈、设置和真实长图生成仍不在本 Spec 内。

## 1. 概述

当前 `pages/assets/index` 已经是 3.0 的素材库 Tab 根页，支持照片、视频、PDF 的上传、处理状态、预览、重命名、分类、删除和失败重试；`pkg-profile/assets/index` 也已有头像选择和作品素材选择的雏形。但创建向导的 `step-visual`、`step-photos`、`step-video`、`step-attachment` 和 `step-works` 仍主要使用各自的手机选择或旧 URL 上传路径，素材库中的已有资源不能稳定回填到演员卡。

更重要的是，素材库文件保存在私有桶中，`access-url` 只提供短时签名地址；演员卡历史字段 `sourceImageUrl`、`photosJson`、`videoUrl` 和 `stillsJson` 持久化的是 URL。不能把素材库签名 URL 直接写入这些字段，否则保存成功后会变成过期死链。本 Spec 以“素材 ID 绑定、服务端归属校验、按用途排序、读取时现签地址、旧 URL 兼容”为唯一数据合同，把素材库和创建向导接成一条可回读的链路。

## 2. 目标与非目标

### 2.1 目标

1. 用户可以从素材库向创建向导选择已有照片、视频和 PDF，并在返回后看到真实选中状态。
2. 向导内新上传的照片、视频和 PDF 必须先进入素材库，再绑定到当前演员卡，避免产生素材库之外的孤立资源。
3. 首图、生活照片、视频简历、作品剧照和附件简历均有明确的用途、类型、数量和排序合同。
4. 私有素材不持久化签名 URL；草稿、AI 扩图、公开观看和复制创建按当前使用场景重新签发或校验地址。
5. 旧版本小程序和历史演员卡继续可读；新字段和新接口以向后兼容方式加入。
6. 3.0 素材选择页、向导资源区、加载 / 失败 / 重试 / 删除 / 回读状态符合 00-221 的蓝白视觉合同。

### 2.2 非目标

- 不修改系统背景图库 `actor_card_background`；它是首页 / `step-visual` 的系统资源，不属于用户素材库。
- 不在本 Spec 实现帮助与反馈、设置页面或真实长图生成引擎。
- 不支持 PPT / PPTX；附件仍只支持真实 PDF 合同。
- 不删除 `source_image_url`、`photos_json`、`video_url`、`stills_json` 等历史字段，不做一次性破坏性数据迁移。
- 不把素材库管理页改成新的 Tab；现有 `pages/assets/index` 继续作为原生 Tab 根页，选择模式由 `pkg-profile/assets/index` 承担。

## 3. 用户故事

- 作为演员，我可以在主视觉、生活照片、视频、剧照和附件步骤中选择已经上传过的素材，而不用重复上传。
- 作为演员，我在向导中上传的新文件会自动出现在素材库，之后可以重命名、分类、复用或删除。
- 作为演员，我可以调整生活照片和剧照的顺序，保存后再次进入向导仍保持该顺序。
- 作为演员，我希望上传中、处理中、失败和重试状态明确可见，取消选择不应被误报成网络失败。
- 作为系统维护者，我希望素材绑定验证用户归属和资源类型，不能通过猜测 `assetId` 越权读取或写入他人素材。
- 作为旧版本用户，我已有的 URL 演员卡仍能打开；新版本接通素材库后不能把旧数据静默清空。

## 4. 功能需求

### 4.1 素材库管理页与选择页分工

**描述**：`pages/assets/index` 继续承担素材管理；`pkg-profile/assets/index` 增加卡片选择模式，不通过原生 Tab 携带 query。

**验收标准**：

- WHEN 从原生 Tab 进入素材库 THEN 直接渲染管理页，照片 / 视频 / PDF 三个 Tab、上传、分页、轮询、预览、重命名、分类、删除和失败重试保持可用。
- WHEN 向导打开选择模式 THEN 使用 `/pkg-profile/assets/index?mode=card-select&requestId=...`，页面标题、媒体类型、分类筛选、单选 / 多选上限和当前已选数量由请求上下文决定。
- WHEN 用户确认选择 THEN 选择页返回结构化 `assetId`、媒体类型、状态、文件名和排序信息；不得把 `accessUrl` 作为持久化结果写入 Pinia 或演员卡。
- WHEN 用户取消或返回 THEN 当前选择会话被清理，不得污染下一次头像、作品或向导选择。
- WHEN 选择页加载、上传或读取失败 THEN 显示错误和重试；用户取消微信文件选择不显示“上传失败”。

### 4.2 向导资源入口统一接入素材库

**描述**：以下用途必须使用素材库资产作为唯一的新数据来源；新上传复用 `uploadActorAsset`，上传完成后立即绑定当前草稿。

| 向导步骤 | 用途码 | 允许素材 | 默认分类 | 上限与规则 |
|---|---|---|---|---|
| `step-visual` | `source_image` | `photo` | `portrait` | 单张；扩图由服务端按 assetId 签发地址 |
| `step-works` | `work_still` | `photo` | `production` | 每部作品最多 3 张；第一张是封面；支持替换、删除、排序 |
| `step-photos` | `life_photo` | `photo` | `lifestyle` | 最多 12 张；支持多选、继续添加、删除、排序 |
| `step-video` | `video_resume` | `video` | `self_intro` | 单个；支持选择、上传、预览、替换、删除、跳过 |
| `step-attachment` | `attachment` | `pdf` | `resume` | 单份；≤20MB、≤20 页；复用 00-214 的 assetId 绑定合同 |

**验收标准**：

- WHEN 向导从素材库选择 THEN 服务端验证 `assetId` 属于当前用户、类型匹配且状态为 `ready`，不接受前端伪造的 URL 作为新绑定。
- WHEN 向导直接上传 THEN 文件先写入 `actor_media_asset`，上传返回的 `assetId` 再进入当前步骤的绑定保存；失败或取消不得产生演员卡脏绑定。
- WHEN 同一资源已被选中 THEN 选择器禁止重复添加，并保留当前顺序。
- WHEN 资源处于 `processing` / `failed` THEN 只能显示状态或重试，不能绑定为可用的演员卡资源。
- WHEN 用户在某一步删除资源 THEN 只删除该演员卡绑定，不删除素材库原文件；素材仍可在素材库或其他演员卡中复用。

### 4.3 素材绑定与旧 URL 兼容

**描述**：新增演员卡素材绑定集合和条目，按用途保存 `assetId` 与排序；旧 URL 字段只作为没有新绑定集合时的历史回退。

**验收标准**：

- WHEN 保存新版本素材绑定 THEN 持久化 `assetId`、用途、关联作品和 `sortOrder`，不持久化私有桶签名 URL。
- WHEN 读取草稿 THEN 返回绑定条目的资源元数据和按需签发的短时预览地址；签名地址过期后可重新读取，不能依赖旧地址永久缓存。
- WHEN 某用途尚无新绑定集合 THEN 按既有字段读取历史 `sourceImageUrl`、`photosJson`、`videoUrl` 或 `stillsJson`；有新绑定集合（包括空集合）后，新集合具有明确优先级，不能因旧字段残留而复活已删除资源。
- WHEN 老版本前端继续调用旧 `saveStep` / `replaceWorks` 合同 THEN 后端继续接受旧字段并保持原有响应结构；新字段为可选增量，不改变旧客户端启动和读取路径。
- WHEN 复制演员卡 THEN 同一用户的素材绑定集合、顺序和附件绑定一并复制；复制后的草稿不共享会被错误删除的临时状态。

### 4.4 排序、数量和保存回读

**验收标准**：

- WHEN 用户拖拽或调整生活照片顺序 THEN UI 立即更新顺序，保存请求按 `sortOrder` 从 0 开始提交，重新进入页面顺序一致。
- WHEN 用户调整某部作品剧照顺序 THEN 第一张始终作为封面，最多 3 张；删除首张后下一张自动成为封面。
- WHEN 数量达到上限 THEN 继续添加入口变为不可用或明确提示，不静默截断已有数据。
- WHEN 保存成功 THEN 当前步骤、绑定集合、步骤状态和页面预览同时回读；不能只显示“保存成功”而保留旧列表。
- WHEN 保存失败或回读失败 THEN 保留用户当前未提交选择、显示重试，并阻断下一步跳转，避免空值覆盖历史数据。

### 4.5 AI 扩图、公开观看和发布兼容

**验收标准**：

- WHEN `step-visual` 使用素材库照片扩图 THEN 新接口接收 `sourceAssetId`，后端校验归属并在调用 AI provider 前现取签名地址；旧 `sourceImageUrl` 入参继续兼容，签名地址不落库。
- WHEN 公开观看页读取已发布演员卡 THEN 服务端根据已发布绑定集合现签图片 / 视频地址，只返回当前卡已绑定且允许展示的资源；无新绑定时回退历史 URL。
- WHEN `settingsJson.order` 或显隐开关存在 THEN 观看页继续按现有合同排序和显隐；本 Spec 不把“真实长图生成”伪装成已完成。
- WHEN 用户删除素材库资源 THEN 如果该资源仍被演员档案、演员卡、作品或已发布卡引用，服务端拒绝删除并返回明确的“素材使用中”错误；先解除绑定才能删除。
- WHEN 新后端缺少素材绑定迁移表或新字段 THEN 新接口返回可识别的能力未部署错误，既有 URL 接口和旧前端不因 SQL 异常白屏。

### 4.6 3.0 视觉和操作合同

- 选择页和向导资源区必须使用 00-221 Token，不重新引入旧棕米色、橙色选中态或 Emoji 图标。
- 图片、视频和 PDF 必须有空、加载、处理中、可用、失败、替换、删除和重试状态；固定底部 CTA 预留安全区。
- 选择按钮、预览、替换、删除、排序和确认操作必须有真实 handler；不能保留“即将开放”假入口。
- 选择页和管理页必须在 `src`、`dist/build/mp-weixin`、`dist/dev/mp-weixin` 三侧核对，遵守 00-219 scoped hash 一致性流程。

## 5. 非功能需求

- 兼容微信基础库 >= 2.25.0；至少验证 iPhone SE、iPhone 15 Pro Max 和常见 Android 宽度。
- 单页默认列表不超过 10 条；选择器超过 10 条分页或触底加载，已选集合不能因翻页丢失。
- 所有 `assetId` 写入路径都必须服务端验归属、类型和 `ready` 状态；不能依赖前端隐藏他人资源。
- 签名 URL 只在响应或 AI 调用内存中使用，不落库、不写日志、不放入长期 Pinia 状态。
- 新增向导代码继续位于 `pkg-actor-card` 分包；选择页复用既有 `pkg-profile` 分包，不把业务模块搬入主包。
- 新增迁移 SQL 必须幂等；生产发版先迁移、再后端、再前端，旧版本仍可读旧字段。

## 6. 约束和决策

1. 00-221 T0-3 中“素材库选择与排序”已由 2026-08-18 用户裁决纳入本 Spec；帮助与反馈、设置、真实长图生成仍另行裁决。
2. 私有素材不转成持久化签名 URL。公开观看需要的地址由服务端在发布卡权限范围内现签；AI provider 使用服务端现取地址。
3. 不通过原生 Tab 路由传递选择 query；选择模式固定使用 `pkg-profile/assets`，以 `requestId` 隔离会话。
4. 设备上传统一进入 `actor_media_asset`；既有 `/api/file/upload/photo|video` 保留给旧客户端，不在本 Spec 删除。
5. 附件步骤沿用 00-214 已完成的 `attachment_asset_id` 三态语义，不新建第二套附件字段。
