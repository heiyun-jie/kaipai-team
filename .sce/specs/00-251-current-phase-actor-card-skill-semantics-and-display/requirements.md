# 演员卡技能特长语义与展示收口

> 状态：实施中（2026-09-02）。
>
> 上游：`00-228`、`00-229`、`00-248`、`00-249`、`00-250`；下游：`00-236` 人工验收。

## 1. 概述

`pkg-actor-card/generate/index` 与公开详情页共用的 `ActorCardRenderer` 当前把演员档案技能、人物类型和作品类型合并展示，并为每个标签生成统一的非事实说明。结果是“短剧、恐怖、古装”等作品题材进入“技能特长”，技能数量被放大，正文出现重复且像虚构的能力描述。

本 Spec 将技能特长改为结构化语义展示：职业特长、职业能力和人物类型 / 戏路分组传输；作品类型只属于拍摄经历；旧扁平 `skills` 字段继续保留兼容；Hero 与正文使用真实技能标签，不生成虚构说明。

## 2. 用户故事

- 作为演员，我希望演员卡上的技能只反映我填写的职业特长和职业能力，不把作品类型当成技能。
- 作为观看者，我希望能区分演员的职业能力、职业特长和角色方向，快速判断是否匹配项目。
- 作为维护者，我希望历史演员卡仍可展示，旧客户端不因新增分组字段而失效。

## 3. 功能需求

### 3.1 技能数据语义边界

- WHEN 后端组装演员卡资料 THEN `works[].workType` 不得写入 `profile.skills` 或任何技能分组。
- WHEN 存在结构化档案字段 THEN `specialtyTags` 归入职业特长，`professionalAbilityTags` 归入职业能力，`roleTypeTags` 归入人物类型 / 戏路。
- WHEN 快照只有旧的扁平 `skills` / `skillTypes` THEN 保留为兼容技能列表，不根据作品类型推断新的技能类别。
- 所有分组值必须 trim、过滤空值并保持首次出现顺序去重。

### 3.2 兼容响应

- `ActorCardPublicRespDTO.ProfileVO` 新增可选 `skillGroups`：`specialty`、`professionalAbility`、`roleType` 三个数组。
- 既有 `profile.skills` 字段保留，不改名、不删除；旧客户端继续读取原字段。
- 生成预览接口与公开接口返回相同的分组结构；不新增数据库字段、不修改持久化合同。

### 3.3 Hero 技能卡

- Hero 固定坐标、尺寸和视觉层级保持 `00-229` / `00-250` 合同不变。
- Hero 最多展示 4 个真实职业能力 / 职业特长标签，优先职业能力，再由职业特长补足。
- 人物类型 / 戏路和作品类型不得出现在 Hero 技能标签中。
- 标签过多时使用稳定的 `+N` 摘要，不改变 Hero 固定高度或造成溢出。
- 无真实技能时显示“技能待完善”。

### 3.4 正文技能区

- 正文“技能特长”只统计职业能力、职业特长和历史未分组技能，不统计人物类型或作品类型。
- 展示采用分组紧凑标签；职业能力、职业特长分别显示标题。
- 没有真实描述字段时只显示技能名称，不生成“能力稳定，可配合角色与拍摄需求”等固定文案。
- 人物类型 / 戏路在非空时以独立“角色方向”分组展示；不计入技能数量。
- 空数据统一显示“技能信息待完善”。

### 3.5 作品类型边界

- `workType` 继续在“拍摄经历”条目的作品元信息中展示。
- 作品类型不得影响技能 Hero、技能正文、基础资料摘要或技能统计值。

## 4. 非功能需求

- `generate/index` 与 `view/index` 继续只使用同一个 `ActorCardRenderer`。
- 前端只使用现有 `$kp-*` Design Token；不改变 Hero 七区坐标、画布尺寸、简介摘要和底部交接。
- `src`、`dist/build/mp-weixin`、`dist/dev/mp-weixin` 三侧 Renderer 与 API 类型同步，WXML/WXSS/JS scoped hash 一致。
- 旧扁平响应、缺失分组字段和空字段均有稳定降级。

## 5. 非目标

- 不修改演员资料编辑页的标签词表。
- 不根据作品题材自动推断演员能力。
- 不自动合并未经产品确认的同义词。
- 不改变扩图、主视觉、个人简介和 Hero 中性交接逻辑。
- 不修改数据库、生产环境、测试数据或正式发布状态。

## 6. 验收标准

- 后端单测证明结构化技能分组来源正确，作品类型不进入技能集合。
- 前端专项门禁证明 Hero 与正文只渲染真实技能标签，固定说明文案已移除。
- 前端专项门禁证明技能数量不包含 `workType` / `roleType`。
- 类型检查、演员卡现有专项门禁、构建和 build/dev 等价检查通过。
- MCP 只读截图确认 `pkg-actor-card/generate/index?cardId=1` 的 Hero 和正文技能区不再显示作品类型，正文无重复虚构说明，生成页与公开页视觉一致。
- 正式容器、正式数据库、正式 Nginx、正式小程序保持不变，正式发布状态仍为 `NOT_AUTHORIZED`。

## 7. 发布兼容

- 新增响应字段为可选扩展，旧前端忽略后继续工作。
- 前后端必须同批进入新的测试 Candidate；当前 Candidate 在实现后失效，必须重新构建、冻结并通过测试环境门禁。
- 无数据库迁移；回滚前端和后端后旧 `skills` 字段仍可用。
