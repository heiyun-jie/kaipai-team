# 演员档案 PDF 简历上传与图片页渲染 Requirements

> 状态：当前执行中 | 优先级：高 | 依赖：03-04、05-02、05-05

## 1. 概述

演员资料编辑页需要支持上传一份 PDF 简历/作品集，并在分享详情页中渲染 PDF 内的内容。当前项目已有头像、照片、视频简历上传，但没有 PDF 文件类型、PDF 元数据存储或详情页文档渲染能力。

本需求的第一版采用“PDF 转图片页”方案：上传 PDF 后由后端将每一页转换为图片并上传到 COS，公开详情页只渲染这些图片页，不在小程序端运行 PDF.js，也不把 PDF 文本 OCR/抽取后自动回填到结构化档案字段。

## 2. 用户故事

- 作为演员，我希望在个人资料中上传已有 PDF 简历/作品集，减少重复录入。
- 作为演员，我希望分享详情页可以直接展示 PDF 简历内容，让项目方看到完整原稿。
- 作为项目方/访客，我希望在分享详情页中顺畅浏览 PDF 的每一页，而不需要额外下载或跳转外部预览。
- 作为研发/运营，我希望 PDF 渲染不增加小程序包体，不依赖前端 PDF 解析库，并且能限制文件大小和页数。

## 3. 功能需求

### 3.1 PDF 上传入口

**描述**：演员资料编辑页新增“PDF 简历”上传模块，允许上传、替换、删除一份 PDF。

**验收标准**：

1. WHEN 演员进入 `pages/actor-profile/edit` THEN 页面展示 PDF 简历模块。
2. WHEN 演员选择 PDF THEN 前端只允许 PDF 文件进入上传流程。
3. WHEN PDF 超过大小限制 THEN 上传前或上传后返回明确错误，不保存到档案。
4. WHEN PDF 上传成功 THEN 编辑页展示文件名、页数和已生成图片页数量。
5. WHEN 演员删除 PDF THEN 保存后公开详情页不再展示 PDF 简历区块。

### 3.2 后端 PDF 文件校验

**描述**：后端新增 PDF 上传能力，校验文件类型、扩展名、文件头、大小和页数。

**验收标准**：

1. WHEN 上传文件不是 PDF THEN 后端拒绝并返回文件类型错误。
2. WHEN 上传文件大小超过限制 THEN 后端拒绝并返回大小错误。
3. WHEN PDF 页数超过限制 THEN 后端拒绝并返回页数错误。
4. WHEN PDF 被加密或无法读取 THEN 后端返回解析失败错误。

### 3.3 PDF 转图片页

**描述**：后端将 PDF 每页渲染为移动端可展示图片，上传 COS，并返回有序图片页列表。

**验收标准**：

1. WHEN PDF 上传成功 THEN 后端返回原 PDF URL、文件名、页数和有序图片页 URL 列表。
2. WHEN PDF 有 13 页 THEN 返回 13 张图片页，顺序与 PDF 页面顺序一致。
3. WHEN 图片页生成失败 THEN 整个 PDF 上传结果不得被标记为可展示成功。
4. WHEN 图片页被公开详情页消费 THEN 前端不需要 PDF.js 或 web-view 才能展示主要内容。

### 3.4 演员档案数据承接

**描述**：演员档案保存和读取接口需要承接 PDF 简历元数据。

**验收标准**：

1. WHEN 编辑页保存档案 THEN `resumePdfUrl`、`resumePdfName`、`resumePdfPageCount`、`resumePdfPageImageUrls` 被保存。
2. WHEN 获取本人档案 THEN 返回 PDF 简历元数据。
3. WHEN 获取公开详情页档案 THEN 返回 PDF 图片页列表，但不暴露额外私密字段。
4. WHEN 未上传 PDF THEN 响应字段为空或空数组，不影响既有资料渲染。

### 3.5 分享详情页渲染

**描述**：公开分享详情页在原有资料内容中新增 PDF 简历区块，按顺序渲染图片页。

**验收标准**：

1. WHEN 档案存在 `resumePdfPageImageUrls` THEN `pages/actor-profile/detail` 展示“PDF 简历”区块。
2. WHEN PDF 图片页列表为空 THEN 不展示该区块。
3. WHEN 用户滚动详情页 THEN PDF 页面按顺序纵向展示，保持原始页面比例。
4. WHEN 图片页加载失败 THEN 单页显示轻量失败占位，不阻断其他页和联系方式操作。
5. WHEN 底部联系操作栏存在 THEN 不遮挡 PDF 最后一页。

## 4. 非功能需求

1. 不引入前端 PDF.js，不显著增加小程序包体。
2. PDF 原稿第一版只作为公开展示附件，不自动回填姓名、经历、照片或账号数据。
3. 图片页应压缩到适合移动端浏览的尺寸，避免公开详情页一次加载过多超大图片。
4. PDF 只允许一份，后续替换覆盖旧元数据。
5. 公开详情页以懒加载图片方式渲染，降低首屏和长页加载压力。

## 5. 约束条件

1. PDF 上传必须走后端封装，前端不直接调用 COS。
2. PDF 文件和图片页必须使用后端生成的 COS URL。
3. 当前不新增 OCR、结构化解析、AI 自动整理或自动回填。
4. 当前不新增多 PDF 附件管理、排序管理或权限分组。
5. 公开分享详情页默认公开展示 PDF 图片页；用户需要主动删除 PDF 才能取消公开展示。

## 6. 验收总则

1. 演员资料编辑页可以上传并保存 PDF 简历。
2. 后端能将 PDF 转成图片页并返回有序 URL。
3. 公开分享详情页能原生渲染 PDF 图片页。
4. 既有头像、照片、视频、拍摄经历和联系方式申请不被破坏。
5. 后端编译、前端类型检查和微信小程序构建通过。
